# 엑셀 취합 도구 (merge-master)

호스트가 Excel(COM)에서 시트를 불러와 취합용으로 설정하고, 앱 안의 웹 서버를 열면 사내 LAN의 참여자들이
브라우저로 접속해 동시에 입력합니다. 마지막에 호스트가 결과를 다시 엑셀로 저장합니다.

- 화면 기준: [`design/취합 협업 와이어프레임.dc.html`](design/) (1a~1i)
- 단계별 계획: 0단계 골격·스파이크 → 1 COM 불러오기 → 2 취합 설정·그리드 → 3 서버·접속 → 4 동시 편집 → 5 엑셀 저장(MVP) → 6 모니터링·히스토리·소통 → 7 안정화·배포

## 구조

```
apps/host/            호스트 UI (Tauri 웹뷰, React)
apps/participant/     참여자 웹 (React) → 빌드 결과를 collect-server가 바이너리에 포함
packages/grid/        공용 가상 그리드 (병합·틀 고정·Excel 서식)
packages/shared/      ts-rs 생성 타입, 표시 형식 유틸
src-tauri/            Tauri 앱: command, 앱 상태
crates/excel-com/     Excel COM: 전용 STA 스레드, IDispatch 래퍼, 시트 읽기, 수식 계산 사본
crates/collect-core/  도메인 모델 (SheetModel·취합 설정·권한 엔진·입력 검사·저장 계획·이력 보기)
crates/collect-server/ axum HTTP/WebSocket 서버 + 세션 액터 (+ collect-dev-server)
crates/collect-store/ 세션 저장소: SQLite(변경 기록·스냅샷 zstd)
fixtures/             테스트용 시트 모델(JSON). 원본 xlsx는 scripts/make-fixture.ps1로 생성
e2e/                  Playwright (설치된 Chrome 사용)
```

## 준비물

Windows 10/11, Excel(데스크톱), Rust stable(MSVC), Node 22+, pnpm 10.

```powershell
pnpm install
```

## 0단계 스파이크 결과

측정 PC: 이 개발 PC, Excel 16, 예산신청서 1,002행 × 9열(병합 443, 수식 1,000, 목록 유효성 1).

| 스파이크           | 목표                                                           | 결과                                                                               |
| ------------------ | -------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| A. COM 읽기 — 값   | < 1초                                                          | 8 ms (`Value2` 한 번)                                                              |
| A. COM 읽기 — 서식 | < 10초                                                         | 0.9초 (분할 정복, 블록 197개 탐색 → 서식 9종)                                      |
| A. COM 읽기 — 전체 | –                                                              | 1.9초, Excel 호출 6,688회 (병합 0.9초가 가장 큼)                                   |
| B. 서버            | 다른 브라우저 간 WS 브로드캐스트, 열린 연결이 있어도 정상 종료 | 통과 (단위 테스트 + E2E). Tauri 앱 안에서 LAN 주소로 서빙 확인 (`pnpm smoke:host`) |
| C. 그리드          | 1,000행 스크롤 60fps 근접                                      | 평균 59fps, p95 17ms, 동시에 그린 셀 최대 287개                                    |

확인된 사항

- Excel 개체 모델은 같은 멤버 이름에 같은 DISPID를 쓴다(`EXCEL_COM_VERIFY_DISPIDS=1`로 검증) → 이름 조회 캐시로 호출 수 절반.
- 한국어 Excel은 '일반' 표시 형식을 `G/표준`으로 돌려준다 → `Application.International(26)`으로 `General`로 정규화.
- PowerShell COM 바인더는 2차원 배열 대입에서 `InvalidCastException`을 낼 때가 있어 픽스처 스크립트는 리플렉션으로 설정한다.

남은 확인(사람이 해야 함)

- 다른 PC·휴대폰에서 `http://<호스트IP>:8080/q4` 접속, Windows 방화벽 허용 대화상자 동작.

## 1단계: 엑셀 불러오기 (1a)

시트를 고르면 **사전 감지**(값·수식 전체 + 위쪽 21행의 병합·굵게만 읽음, 예산신청서 0.3초)로 범위·머리글·틀 고정을
채우고 곧바로 전체를 읽어 미리보기를 보여 준다. 범위·가져올 항목을 고치면 입력이 멈춘 뒤 다시 읽고(앞선 읽기는 취소),
머리글 행 수·틀 고정 열은 다시 읽지 않고 미리보기에 바로 반영한다. '불러오기 → 취합 설정'을 누르면 그 상태로 확정된다.

감지 규칙 (`crates/collect-core/src/detect.rs`, Excel 없이 단위 테스트)

- 표 범위: 아래·옆의 빈 행·열을 자르고, 위쪽의 빈 행·제목 행(내용 1칸)·안내 행(표 너비 절반 미만)을 건너뛴다.
- 머리글: 첫 행이 모두 글자면 머리글. 그다음 행은 위 머리글의 세로 병합에 걸쳐 있거나, 모두 글자이면서 굵게/가로 병합이면 머리글.
- 열 이름: 가장 아래 머리글 행부터 위로 올라가며 처음 보이는 글자(병합 고려).
- 배정 기준 열 후보: 머리글 낱말(담당·작성자·이름…), 사람 이름 모양(한글 2~4자, 팀·부·비 등으로 끝나지 않음), 반복 여부로 점수.

Excel에서 확인한 함정

- 여러 행 범위의 `EntireRow.Hidden`은 섞여 있어도 Null이 아니라 False → 숨김은 행 높이·열 너비 0으로 판정한다.
- `Window.SplitRow/SplitColumn`은 창이 작으면 '보이는 칸 수'로 줄어든다(앱이 띄운 숨은 Excel 창에서 실제로 발생) →
  스크롤 창을 1행·A열로 보내 Excel이 막아 준 위치를 읽고 되돌린다.
- 비활성 시트의 틀 고정은 화면 갱신·이벤트(VBA `Worksheet_Activate`)를 끄고 잠깐 활성화해 읽은 뒤 원래 시트·통합문서로 되돌린다.
- '파일 열기'는 이미 열린 파일이면 그 문서를, 실행 중인 Excel이 있으면 그 Excel을(사용자에게 보임), 없으면 숨은 인스턴스를 쓴다.
- Excel이 닫히면(RPC_E_DISCONNECTED 등) '다시 찾기' 안내, 바쁘면(편집 중인 셀·대화상자) 8초 재시도 후 안내, 100만 셀 초과 범위는 읽기 전에 거절.

## 2단계: 취합 설정 (1b)

불러온 시트를 확정하면 설정 초안이 만들어지고(`CollectConfig::suggest`), 호스트가 1b 화면에서 고친다.

- **역할 브러시**: 범위를 고르고(드래그·Shift·열/행 머리글 클릭) 조회조건·입력 영역·입력 금지·필수·담당자 배정·지우개를 누른다.
  데이터 행 전체(또는 머리글 포함)를 고르면 **열 단위** 설정, 일부만 고르면 **셀 예외**가 된다.
- **오른쪽 패널**: 열 속성(역할·필수·조회·형식·단위·목록 항목·안내), 셀 예외(메모), 담당자 배정(행 배정 기준 열·명단·범위 배정),
  참여자 권한(서식 변경 불가/배경색만/허용, 남의 행 읽기 전용/숨김, 필터·정렬, 행 추가).
- **서식 도구 줄**: 글꼴·크기·굵게·기울임·밑줄·글자색·채우기·테두리(모두/바깥쪽/없음)·병합/해제·맞춤.
- **참여자 시점으로 보기**: 명단의 한 사람으로 보면 남의 행은 회색(또는 '숨김'이면 사라짐), 내 칸만 흰색이다.

권한 규칙 (`crates/collect-core/src/access.rs`)

- 입력 가능 = (배정 행 ∪ 배정 범위) ∩ 입력 영역 − 입력 금지 − 수식 − 머리글 − 숨긴 행·열 − 병합에 덮인 칸.
- 셀 예외는 열 역할을 덮어쓰고, 같은 칸이면 **입력 금지가 항상 우선**한다. 범위 배정은 행 담당자의 권한에 더해진다(둘 다 입력 가능).
- 명단 = 행 배정 기준 열의 이름(병합 고려, 나온 순서) + 직접 추가한 이름 + 범위 배정 받은 이름.

기본 제안 규칙: 수식 열·배정 기준 열·거의 다 채워진 열은 입력 금지, 30% 이상 빈 열은 입력 영역, 값이 2~50가지로 반복되는
입력 금지 글자 열은 조회조건, 목록 유효성은 목록 형식, 숫자 열은 숫자 형식(머리글 괄호 안을 단위로: `금액 (천원)` → 천원).

설계 결정

- 판정은 **Rust 한 곳**에서 한다. 화면은 셀당 1바이트 상태(`ConfigView.flags`, base64)를 받아 그리기만 하므로 1b 화면·참여자
  시점 미리보기·3단계 서버(`project`)가 같은 규칙을 쓴다. 상태 비트 값은 `packages/shared/src/flags.ts`와 Rust `access::flag`가 같아야 한다.
- 서식 도구 줄의 변경은 앱 안의 시트에 반영되어 참여자에게 보인다. 저장할 때 '앱에서 바꾼 서식·병합도 반영'을 켜면 Excel에도 쓴다(5단계).

## 3단계: 협업 서버와 접속 (1c · 1e)

구조: **세션 액터**(`crates/collect-server/src/session/`) 하나가 시트·설정·권한 엔진·참여자·승인 대기를 소유한다.
WebSocket 연결과 호스트 명령은 채널로 명령만 보내고, 호스트 화면(1c 접속자 표)은 `watch` 스냅샷을 Tauri 이벤트(`participants`)로 받는다.
(4단계부터 세션이 시트·설정의 유일한 주인이다 — 아래 4단계 참고.)

접속 흐름(프로토콜 v1, `protocol.rs`)

- 이름만 입력 → 명단(행 배정 기준 열 + 추가 이름 + 범위 배정)에 있으면 바로 입장(`welcome`), 없으면 `pending` → 호스트가
  '배정 후 승인'(범위 지정 가능)하거나 '거부'.
- 같은 이름이 접속 중이면 `dupName` → '이 기기로 전환'(`switchDevice`)하면 앞 기기는 `kicked(switchedDevice)`.
- 입장하면 재접속 토큰을 받아 브라우저(`localStorage`, 주소 경로별)에 둔다. 새로 고침·연결 끊김 뒤에는 토큰으로 이름 입력 없이 다시 들어온다.
- 시트는 입장한 뒤에만, **그 사람 기준**(`project`)으로 보낸다. '남의 행 숨김'이면 남의 행 값은 보내지 않는다. `/api/sheet`는 없앴다.
- 프레즌스: 접속 중 / 자리 비움(3분 무활동) / 미접속, 다른 사람 커서는 이름표로 보인다.

호스트 1c: 제목·요청자·안내·마감, 네트워크·포트·주소 경로, 접속 주소·안내문 복사, '마감 후 자동 읽기 전용', 방화벽 확인
(읽기 전용, 규칙 추가는 사용자가 UAC로 승인), 접속자 표(상태·배정 요약·현재 위치·필수 진행률·연결 끊기).

개발 서버: `pnpm dev:server`는 `--dev-admin`으로 `/__dev/approve|reject|kick|snapshot`을 켠다(앱에는 없음, E2E용).
`--others-hidden`, `--required F,H`, `--title`, `--requester` 옵션이 있다.

## 4단계: 동시 편집 (1f · 1g)

**세션 구조**: 시트를 확정하면 세션이 생기고(`SessionHandle::spawn`) 앱이 끝날 때까지 산다. 서비스 시작·중지는 그 세션에
HTTP 서버를 붙였다 뗄 뿐이라, 멈췄다 다시 열어도 입력한 값·이력·진행률이 그대로다. 호스트(1b·1c)는
`session.with(|s| …)`로 세션 안에서 시트·설정을 읽고 고친다(설정을 고치면 `s.changed()` → 권한 재계산 + 접속자에게 새 시트).
다시 불러와 확정하면 `s.replace()`로 셀 버전·잠금·이력을 새로 시작한다.

**셀 수정**(프로토콜 v2, `setCells{batch, cells:[{row,col,value,base}]}`): 서버가 칸마다 권한 → 마감 → 남의 편집 잠금 →
형식 검사·정규화(`collect_core::validate`, 화면도 같은 규칙의 TS판 `packages/shared/src/validate.ts`로 즉시 검사) → 적용·버전 증가 →
이력(`ChangeEntry`) 순으로 처리한다. 보낸 사람에게는 `applied`(정규화한 값·새 버전·거절 칸과 이유·충돌 칸), 다른 사람에게는
`cells`를 보낸다('남의 행 숨김'이면 그 행이 보이는 사람에게만). 필수 진행률은 다시 세지 않고 증분으로 고친다.

- **충돌**: `base`가 지금 버전보다 낮고 마지막으로 바꾼 사람이 내가 아니면 나중 입력(내 값)으로 덮어쓰고 '충돌 칸'으로 알린다.
- **편집 잠금**: 편집기를 열면 `lock`, 확정하면 서버가 풀고 취소하면 `unlock`. 한 사람은 한 칸만 잠근다. 연결이 끊기면 30초 유예
  (다시 붙으면 이어서), 10분 넘게 잡고 있으면 풀린다(편집기는 1분마다 다시 잡음). 호스트는 1c ⋯ 메뉴 '편집 잠금 해제'로 즉시 푼다.
- **마감**: '마감 후 자동 읽기 전용'이면 마감 시각(로컬)이 지나는 순간(5초 주기 점검) 모두에게 `readOnly` → 입력·잠금 거절.
- **같은 묶음 다시 보내기**(오프라인 대기열 재전송)는 한 번만 반영한다(`이름 + 묶음 ID`).
- **서식**: 참여자 권한이 '배경색만'·'허용'일 때만, 내가 입력할 수 있는 칸에만(`format` → 모두에게 `styles`).

**수식 재계산**(`excel_com::calc`, `src-tauri/src/recalc.rs`): 확정할 때 원본을 `SaveCopyAs`로 임시 파일에 복사해 **별도의 숨은
Excel**에서 연다(매크로·이벤트 끔, 계산 수동). 참여자 입력을 300ms 모아 사본에 쓰고 `Calculate` 뒤 수식 칸을 한 번에 읽어
바뀐 칸만 보낸다(`cells`, `by: ""`). 원본은 저장 전까지 건드리지 않는다. 사본을 열 수 없거나 Excel이 닫히면 1c에 '저장할 때 계산'으로
표시하고 취합은 계속한다. 글자는 `'`를 붙여 써서 숫자·수식으로 바뀌지 않게 한다. 사본은 1a 통합문서 목록에 보이지 않는다.

**참여자 그리드(1f)**: 방향키·Enter·Tab(병합·숨긴 행 건너뜀), 입력하면 바로 편집(Excel '입력' 모드: 방향키로 확정+이동),
F2·더블클릭은 '편집' 모드, Esc 취소, Alt+Enter 줄바꿈, Delete 범위 지우기, Backspace, Ctrl+Z/Ctrl+Y(내 변경만, 묶음 단위 —
그 뒤 남이 바꾼 칸은 건너뜀), Excel 복사·붙여넣기(TSV, 한 칸을 범위에 붙이면 채우기, 형식이 틀리거나 남의 칸은 건너뛰고 알림),
목록 칸은 ▾ 또는 Alt+↓로 드롭다운. 잠긴 칸은 '🔒 이서연' 이름표와 '끝나면 알려 주기'. 조회조건(호스트가 지정한 열)·내 담당만·
필수 미입력만 필터(걸 때 한 번 계산해 입력하는 동안 행이 사라지지 않음, 걸러진 행은 높이 0 → 병합은 보이는 행으로 다시 그림).
상태 바: 실시간 동기화 / 저장 중 / 오프라인(대기 N건), 내 변경 수, 마지막 저장 시각, 편집 중인 칸.

- **낙관적 반영**: 입력은 바로 그리고 답이 오면 서버 값으로 바꾼다. 답을 기다리는 칸(파란 모서리)은 남의 수정이 와도 내 값을 보인다.
- **오프라인 대기열**: 보내지 못한 묶음은 IndexedDB(주소 경로·이름별)에 두고, 다시 들어오면(새로 고쳐도) 처음 본 버전과 함께 보낸다.
- **한글 입력**: 활성 칸에 투명 편집기를 미리 놓아 두어 첫 글자부터 조합을 받는다(포커스가 옮겨지기 전에 그리드로 온 첫 글자도 받음).

**행 단위 입력(1g)**: 내 담당 행 목록(검색, 전체/미입력 탭, 미입력 먼저), 이전·다음 미입력, 읽기 전용 값 요약 띠(빗금, 수식 포함),
형식별 입력(숫자+단위, 목록은 칩, 날짜, 글자), 즉시 검사, 칸을 벗어나면 자동 저장, 이 행 변경 이력, 같은 비목 비교, '그리드에서 이 행 보기'.

시험: 서버 단위 테스트(편집·검사·잠금 유예/만료·충돌·중복 묶음·마감·숨김 정책·이력·서식 정책·재계산 요청·교체) +
WebSocket 통합(서버를 멈췄다 다시 열어도 값 유지), Excel 통합(`calc_copy_recalculates_without_touching_original`),
TS 단위(검사·편집 상태·필터·붙여넣기·TSV), E2E 14개(`e2e/editing.spec.ts`), 호스트 스모크(입력 → 진행률, G열 재계산, 잠금 해제).
개발 서버 관리 API에 `/__dev/unlock`·`/__dev/config`(마감·서식 정책)·`/__dev/formulas`(재계산 결과 흉내)가 더해졌다.

알아 둘 것

- 개발 서버(release)는 참여자 웹을 **빌드할 때 바이너리에 넣는다**(rust-embed). 웹을 고친 뒤 이미 떠 있는 서버로 E2E를 돌리면
  옛 화면이 나온다 → 서버를 다시 빌드하거나 끄고 `pnpm e2e`.
- 디스크가 부족하면 `target/debug/incremental`(수 GB)을 지워도 된다(다시 만들어짐). `CARGO_INCREMENTAL=0`으로 빌드하면 쌓이지 않는다.

## 5단계: 엑셀로 저장 · 취합 마감 (6 저장·마감, MVP)

화면(와이어프레임에 없던 화면을 새로 정의): 왼쪽 **취합 요약**(필수 완료율, 바뀐 칸·입력한 사람·변경 기록 수·마지막 변경,
담당자별 필수 진행률과 비어 있는 칸 주소), 오른쪽 **엑셀로 저장**(저장 위치·함께 넣기·저장 뒤, 저장 전 확인, 결과).

- **저장 위치**: '다른 이름으로 저장'(기본 `원본명_취합_YYYYMMDD.xlsx`, 원본 폴더) — 원본을 `SaveCopyAs`로 복사해 **별도의 숨은
  Excel**에서 쓰고 저장한다(원본은 그대로). '원본 통합문서에 반영하고 저장' — 원본에 쓰고 `Save`(저장한 적 없는 새 문서·읽기 전용
  문서는 막음, Excel에서 저장하지 않은 변경이 있으면 함께 저장된다고 알림). 원본이 닫혔으면 저장할 때 다시 연다.
- **무엇을 쓰나**(`collect_core::export::plan`): 기준 시트와 값이 다른 칸만, 수식 칸·병합에 덮인 칸은 빼고. 열마다 이어진 칸은
  `Value2` 배열 한 번으로(병합 머리 칸은 따로). 글자는 앞에 `'`를 붙여 `0012`·`=1+1`·`1-2`가 숫자·수식·날짜로 바뀌지 않게 한다
  (표시 형식이 `@`인 칸은 그대로). 날짜는 일련번호, 빈 값은 지우기.
- **함께 넣기**: '변경 이력' 시트(시각·사용자·셀·항목·이전 값·새 값, 이름이 겹치면 `변경 이력 2`), 바뀐 칸 노란색 표시,
  앱에서 바꾼 서식(글꼴·채우기·맞춤·테두리)·병합 반영(바뀐 것이 있을 때만 보임).
- 쓰는 동안 화면 갱신·이벤트·자동 계산·경고를 끄고 끝나면 되돌린다(되돌릴 때 수식이 다시 계산된 뒤 저장). 저장한 뒤 쓴 칸을 다시 읽어
  확인한다(결과에 '다시 읽어 확인함' 또는 다른 칸 수).
- **원본 변경 감지**(`export::compare`): 저장 직전에 불러온 범위를 다시 읽어, 쓸 칸 중 불러온 뒤 Excel에서 직접 고친 칸(충돌)을 보여 주고
  칸마다 '취합 값' / 'Excel 값'을 고르게 한다. 'Excel 값'을 고르면 그 칸은 쓰지 않고 취합 값도 Excel 값으로 바꾼다(참여자에게 알림,
  이력에 `Excel(원본)`). 취합하지 않는 칸이 많이 바뀌었으면(20칸 넘게, 비교한 칸의 20% 넘게) 행·열을 넣거나 지워 표가 밀린 것으로 보고
  '그래도 저장'을 확인해야 저장한다.
- **기준 시트**: 세션이 불러온 시점의 시트를 따로 들고 있다(`Shared::baseline`). 원본에 반영하면 쓴 값(과 서식)이 새 기준이 되어,
  다시 저장할 때는 그 뒤에 바뀐 칸만 쓴다. 다른 이름으로 저장은 기준을 바꾸지 않는다.
- **저장 뒤**: 서비스 계속 / 읽기 전용으로 전환(취합 마감 — 참여자에게 '호스트가 취합을 마감했습니다', 입력·잠금 거절) / 서비스 종료.
  '저장 없이 취합 마감'·'취합 다시 열기' 버튼도 있다. 사이드바에 '취합 마감됨'.

시험: collect-core 단위(바뀐 칸·블록·글자 보존·서식/병합·이력 표·충돌/표 밀림·요약), 세션 단위(기준·호스트 값·마감/다시 열기),
Excel 왕복(`tests/save.rs`: 사본 저장 → 다시 열어 값·글자·수식 재계산·굵게·병합·표시색·이력 시트 확인, 원본에 반영 → 닫고 다시 열어 확인,
충돌 감지·Excel 값 유지, 같은 이름·다른 형식 거절), E2E(마감·다시 열기), 호스트 스모크(다른 이름으로 저장 → 별도 Excel로 열어 확인,
원본에 반영 + 마감 → 참여자 읽기 전용, 기준 갱신으로 바뀐 칸 0, `--running-excel`에서는 사용자 Excel에서 고친 칸 충돌 → Excel 값 유지).
개발 서버 관리 API에 `/__dev/close`(마감·다시 열기)가 더해졌다.

## 6단계: 모니터링 · 히스토리 · 소통 (1d · 1h · 1i)

**4 진행 모니터링(1d)**: 전체 필수 진행률과 마감 카운트다운, 공지 보내기·선택 셀 강조·채팅(안 읽은 수)·스냅샷 버튼.
조회조건·필수 미입력만·최근 삭제된 셀(1시간 안에 지워져 지금도 빈 칸) 필터, **담당자별**(누르면 그 사람 행만), **열별 완료**
(누르면 그 열의 필수 미입력 행만). 그리드는 세션의 셀 변경 피드(`HostEvent`, broadcast → Tauri 이벤트 `sheet-changes`)로 바뀐 칸만
고쳐 그리고, 편집 중인 칸은 '이름 · 잠금', 커서는 이름표, 필수 미입력은 빨강, 강조한 칸은 노랑. **실시간 활동**: 최근 묶음(편집 중인
사람 포함), 삭제가 든 여러 칸·10칸 넘는 묶음·스냅샷 복원은 빨간 묶음으로 띄우고 '되돌리기'·'셀로 이동'.

**소통(1i)**: 공지(대상 전체·미완료자·선택한 사람, '중요'는 참여자 화면 위에 확인할 때까지 고정, 읽음 집계, 안 읽은 사람에게 다시
보내기), 셀 강조(선택 범위, 보일 사람 담당자·모두 — '남의 행 숨김'이면 그 행이 보이는 사람만, 노란 표시 + 말풍선 + '셀로 이동'
알림, 확인 집계, 해제), 채팅(참여자는 전체·호스트에게만, 호스트는 전체·1:1, `#F7`·`#F7:H7` 참조를 누르면 그 칸으로, 1,000자·10초에
10통 제한, 글은 글자로만 그려 HTML을 해석하지 않는다). 받는 사람은 보낼 때 명단에서 정하고, 나중에 들어온 사람은 `welcome`으로 받는다.
호스트 화면에는 `CommsSnapshot`을 따로 내보낸다(이벤트 `comms`).

**5 히스토리(1h)**: 셀 변경 기록(`collect_core::history`)을 묶음으로 보여 준다. 칸마다 종류(입력·수정·삭제·되돌림)와 묶음 출처
(붙여넣기·범위 삭제·실행 취소·다시 실행·되돌림·스냅샷 복원·Excel 값 유지 — 참여자가 `setCells`의 `origin`으로 보낸다). 필터: 기간·
사용자·종류·셀/범위·값 검색, '더 보기', CSV 내보내기(Excel용 BOM). 칸 '되돌리기'·'묶음 복원'은 그 뒤에 다시 바뀐 칸이 있으면 묻고
덮어쓴다. 셀 타임라인(원본 → 기록 → 현재)에서 '이 값으로'. **스냅샷**: 불러온 원본, 15분마다 자동(그사이 바뀐 것이 있을 때만),
'지금 저장', 복원 직전(복원도 되돌릴 수 있게). 지금과 다른 칸 수·이후 바꾼 사람, '비교 보기'(앞 500칸), '이 시점으로 복원'.
호스트의 되돌리기·복원도 참여자 입력처럼 버전·이력·진행률에 반영되고 모두에게 간다.

**참여자**: 상단 중요 공지(확인), 툴바 '알림·채팅·셀 이력' 패널, 오른쪽 클릭 → 셀 이력. 셀 이력에서는 **내가 바꾼 마지막 값**만
되돌릴 수 있다(그 밖에는 채팅으로 호스트에게 요청).

**저장소(`crates/collect-store`)**: 시트를 확정할 때마다 `%LOCALAPPDATA%\com.mergemaster.host\sessions\YYYYMMDD-HHMMSS.sqlite`를
만들고 변경 기록(`changes`)·스냅샷(`snapshots`, 셀 값 JSON을 zstd로, 1,000행 × 9열이 수 KB)·메타(통합문서·시트)를 남긴다. 쓰기는 전용
스레드가 하므로 세션 액터가 멈추지 않는다. 앱을 다시 켤 때 이 파일에서 되살리는 일은 7단계에서 한다.

프로토콜 v3(공지·강조·채팅 메시지, `setCells.origin`, `welcome`에 공지·강조·채팅). 바로잡은 것: 호스트 작업(`with`)의 답을 접속자 표·
소통 상태를 내보낸 **뒤에** 돌려준다. 전에는 답이 먼저 와서, 다시 확정한 직후 1c 표가 옛 명단을 계속 보이는 경우가 있었다.

시험: collect-core(종류·묶음·필터·쪽 나누기·되돌리기 계획·스냅샷 차이·CSV), collect-store(압축 왕복, 기록·스냅샷 저장·초기화),
세션(공지 대상·읽음, 강조 대상·숨김 정책·확인·해제, 채팅 경로·1:1·속도 제한, 묶음 출처, 스냅샷·복원·복원 되돌리기, 자동 스냅샷,
저장소, 호스트 피드, 답보다 먼저 내보내기), E2E 4개(`e2e/comms.spec.ts`: 중요 공지·읽음, 강조·셀로 이동·해제, 채팅·#셀 참조,
셀 이력 되돌리기·묶음 출처), 호스트 스모크(모니터링 실시간 반영·담당자 필터·범위 삭제 빨간 묶음 되돌리기·중요 공지 읽음·셀 강조 확인·
채팅 1:1, 히스토리 묶음·셀 타임라인·CSV·스냅샷 비교·복원). 개발 서버 관리 API에 `/__dev/notice`·`highlight`·`highlight/clear`·
`chat`·`comms`·`history`가 더해졌다.

아직 안 되는 것: 앱을 다시 켰을 때 세션 복구·공지·채팅을 파일에 남기기(7단계), 호스트가 그리드에서 직접 입력, 행 추가.

## 7단계: 안정화 · 보안 · 패키징

### 세션 복구

앱이 죽거나(강제 종료·PC 재시작) 호스트가 앱을 닫았다가 다시 켜도 취합을 이어서 한다.

- **무엇을 남기나**: 6단계의 기록 파일(`sessions\YYYYMMDD-HHMMSS.sqlite`)에 변경 기록·스냅샷과 함께 시트·기준 시트·취합 설정·
  소통(공지·강조·채팅·읽음)을 zstd로 압축해 `blobs` 테이블에 둔다. 시트는 통째로 바뀔 때(확정·서식·복원·Excel 값 유지·스냅샷)만 다시 쓰고,
  그 사이의 입력은 변경 기록에 이미 있으므로 되살릴 때 시트 뒤의 기록을 다시 적용한다. 셀 버전·마지막 입력자·이미 반영한 묶음 번호도
  기록에서 다시 만들어, 참여자가 다시 보낸 묶음은 한 번만 반영된다. 서비스 상태(포트·경로·켜짐)와 마감 여부는 메타에 남긴다.
- **이어서 하기**: 앱을 켜면 1a 위에 '지난 취합' 배너(통합문서·시트·변경 수·마지막 변경·다시 열 서비스 포트)가 뜬다.
  '이어서 하기' → 세션을 되살리고 → 앞 앱이 남긴 숨은 Excel을 정리하고(`Session::adopt_orphans`) → 계산 사본을 다시 열고 →
  서비스가 켜져 있었으면 **같은 포트·같은 경로**로 다시 연다(포트를 다른 프로그램이 쓰고 있으면 알리고 취합은 계속). 참여자 브라우저는
  0.5~8초 간격으로 다시 붙어 이름(토큰)으로 다시 입장하고, 끊긴 동안 입력한 값(대기열)을 보낸다.
- **남은 Excel 정리**: 앞 앱이 띄운 계산 사본(임시 폴더 `merge-master\calc-*`)은 닫고 Excel을 끝낸다. 죽은 앱이 쥐고 있던 COM 참조
  때문에 `Quit`만으로는 몇 분 넘게 남아 있어서, 3초 안에 끝나지 않으면 그 프로세스를 끝낸다(앱이 띄운 것으로 확인한 인스턴스만).
  숨은 Excel에 열린 원본은 이 앱이 띄운 것처럼 받아들여 앱을 닫을 때 함께 닫는다(앞 앱이 함께 열어 둔 다른 파일도 저장된 상태면 함께 닫는다. 저장하지 않은 변경이 있는 문서가 있으면 다른 프로그램의 작업일 수 있어 그 Excel은 끝내지 않는다). 사용자가 보는 Excel은 건드리지 않는다.
- '버리고 새로 시작'을 누르면 그 파일은 다시 묻지 않는다(파일은 남는다). 새로 불러와 확정해도 배너는 닫힌다. 기록 파일은 최근 20개만
  남기고 앱을 켤 때 지운다.

### 부하 시험 (`pnpm load`)

`crates/collect-server/tests/load.rs`: 1,000행 × 10열, 30명이 각자 실제 WebSocket으로 접속해 20초 동안 자기 행에 초당 2.5칸씩 입력하고
커서를 초당 5번 움직인다(중간에 한 명이 272칸 붙여넣기). 같은 PC에서 두 번 잰 결과(release 빌드):

| 항목                                       | 1회                                                   | 2회(최종 코드)                                      |
| ------------------------------------------ | ----------------------------------------------------- | --------------------------------------------------- |
| 처리량                                     | 입력 묶음 73/초 · 서버가 보낸 메시지 6,398/초         | 입력 묶음 73/초 · 서버가 보낸 메시지 6,365/초       |
| 반영 지연(보낸 뒤 다른 사람 화면 도착까지) | 51,156건: p50 2.0 · p95 10.1 · p99 11.8 · 최대 78.6ms | 51,185건: p50 1.6 · p95 3.8 · p99 6.3 · 최대 99.6ms |
| 확인 지연(`applied`)                       | p50 1.8 · p95 6.9ms                                   | p50 1.3 · p95 4.3ms                                 |
| 붙여넣기 272칸 확인까지                    | 6.4ms                                                 | 2.6ms                                               |
| 끝난 뒤 서버 값 ≠ 마지막 입력              | 0칸                                                   | 0칸                                                 |

목표(LAN 반영 지연 < 100ms)를 p95·p99로는 넉넉히 넘는다. 최대값은 실행마다 크게 달라(78.6 / 99.6ms) 드물게 튀는 경우가 있다
(같은 PC에서 클라이언트 30개와 서버가 CPU를 나눠 쓰는 영향이 섞여 있다). 실제 LAN에서는 여기에 망 왕복 시간(사내 유선 보통 1ms 안팎)이
더해진다.

### 보안

참여자 서버는 사내 LAN의 HTTP 서버다. 막아 둔 것:

- **WebSocket**: Origin 검사(Origin이 없거나, 접속한 주소와 같거나, loopback일 때만 — 참여자가 연 다른 사이트의 페이지가 그 브라우저를
  통해 붙는 것을 403으로 막는다), 메시지 4MB, 연결마다 초당 50통(순간 200통)까지 — 넘는 메시지는 버리고 경고하며, 500통을 버리면 끊는다.
- **입력 길이**: 이름 20자, 셀 글자 2,000자, 한 묶음 20,000칸, 공지 2,000자, 강조 메모 500자, 채팅 1,000자(10초에 10통), 토큰 64자,
  묶음 번호 80자.
- **HTTP 응답 헤더**: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, CSP(`default-src 'self'`,
  `frame-ancestors 'none'`, `form-action 'none'` 등). 정적 파일은 내장 자산만(경로 탈출 없음).
- **서버가 강제하는 것**: 시트는 입장한 연결에만 보낸다(`/api/sheet`는 404). '남의 행 숨김'이면 남의 행 값을 아예 빼고 보낸다.
  권한·입력 형식·마감(마감 시각·호스트 마감) 검사는 서버에서 한다. 서비스를 중지하면 포트를 닫는다(시험으로 확인).

**알고 쓰기(구조상 한계)**

- **이름만으로 입장한다.** 주소를 아는 같은 망의 누구든 명단에 있는 이름을 대면 그 사람으로 들어올 수 있다. 그 사람이 접속 중이면
  '이 기기로 전환'을 물으며, 전환하면 원래 사람은 ‘다른 기기(창)에서 같은 이름으로 접속해 … 끊겼습니다’ 안내를 본다. 명단에 없는 이름은 호스트가 승인해야
  들어온다. 호스트 접속자 표에 IP가 보이고, 모든 입력은 이름·시각과 함께 기록되어 되돌릴 수 있다.
- **암호화하지 않는다(HTTP).** 같은 망에서 오가는 값을 엿볼 수 있다. 급여·개인정보처럼 민감한 자료에는 쓰지 말고 신뢰할 수 있는
  사내망에서만 쓴다. 접속 경로(`/q4` 같은 slug)는 비밀번호가 아니다.
- 권하는 운영: 필요할 때만 서비스를 켜고 끝나면 중지, 남의 값을 보일 필요가 없으면 '남의 행 숨김', 명단 밖 이름은 승인하기 전에 확인.

### 패키징 · 버전 · 서명

- `pnpm app:build` → 참여자 웹 빌드 → `tauri build`(호스트 화면 빌드, release 실행 파일, NSIS 설치 파일) →
  `release/merge-master_<버전>_x64-setup.exe`와 `SHA256SUMS.txt`.
- **설치 파일**: NSIS, 현재 사용자 설치(관리자 권한 없이 `%LOCALAPPDATA%` 아래에 설치), 한국어 설치 화면, 시작 메뉴 '엑셀 취합 도구'.
  사내망(인터넷 없음)에서도 설치되도록 **WebView2 오프라인 설치 파일**을 넣는다(설치할 PC에 WebView2가 없을 때만 조용히 설치).
  그래서 설치 파일이 약 211MB다(WebView2 설치 파일이 약 204MB, 앱은 압축해서 약 7MB — 실행 파일 19MB). 빌드하는 PC는 처음 한 번 NSIS 도구와 WebView2 설치
  파일을 내려받는다(이후 캐시). `MM_WEBVIEW=bootstrapper`로 빌드하면 작은 부트스트래퍼를 넣은 `…-bootstrap-setup.exe`가 된다(WebView2 부분이 1.7MB로 줄어 10MB 안팎,
  WebView2가 없는 PC는 설치할 때 인터넷 필요 — Windows 11과 업데이트된 Windows 10에는 이미 있다).
- **방화벽**: 설치할 때가 아니라 처음 서비스를 열 때 1c의 '방화벽 확인'으로 규칙을 추가한다(그때 관리자 승인).
- **버전**: `Cargo.toml`의 `[workspace.package] version` 하나가 기준이다(`pnpm bump 1.0.1`, `pnpm bump patch`). Tauri가 이 값을 설치 파일
  이름·제품 버전에 쓰고, 호스트 사이드바 아래에 `v1.0.0`으로 보인다. 지금 버전은 1.0.0.
- **코드 서명**(선택, 환경 변수): `MM_SIGN_THUMBPRINT`(Windows 인증서 저장소의 코드 서명 인증서 지문 → signtool, sha256,
  타임스탬프 `MM_SIGN_TIMESTAMP` 기본 `http://timestamp.digicert.com`) 또는 `MM_SIGN_COMMAND`(다른 서명 도구, 파일 자리 `%1`).
  Tauri가 실행 파일·설치 파일을 모두 서명하고 스크립트가 설치 파일의 서명을 `Get-AuthenticodeSignature`로 확인한다(인증서가 없어 이
  경로는 실제로 돌려 보지 못했다). 서명하지 않으면 설치할 때 SmartScreen이
  '알 수 없는 게시자'로 경고한다.
- `pnpm smoke:release`는 release 실행 파일(내장 화면 `tauri.localhost` · 서버에 내장된 참여자 웹)로 호스트 스모크 전체를 돌린다.

### 시험

collect-server: 보안(헤더·다른 Origin 403·폭주 연결 경고 후 끊김·중지하면 포트 닫힘), 복구(`persist_tests.rs`: 입력·서식·소통·마감을
되살리고 이어서 쓰기, 시트 블롭 뒤 기록 되짚기, 서비스 중에 다시 확정해도 새 기록 파일에 서비스 상태가 옮겨짐), 부하(위 표). collect-store: 블롭·`peek`·초기화. excel-com(`tests/orphans.rs`): 앞 앱이 원본과
계산 사본을 연 채 죽음 → 새 앱이 계산 사본을 닫고 파일을 지우고 원본을 받아들임 → 닫을 때 앞 앱의 Excel 두 개가 모두 끝남(같은 Excel에 함께 열린 다른 파일 포함), 저장하지 않은 문서가 있는 Excel은 끝내지 않음.
src-tauri: 기록 파일 20개만 남기기. 호스트 스모크 `[7 세션 복구]`: 서비스·참여자 접속 중에 앱을 `taskkill /F` → 참여자 오프라인 ·
그동안 입력은 대기열 → 다시 켜면 '지난 취합'(포트 표시) → '이어서 하기' → 진행 화면 · 죽기 직전 값 · 같은 포트로 서비스 → 참여자 자동
재접속 · 대기열 입력 반영 → 계산 사본 Excel 교체 · 이어서 입력하면 G열 재계산 → 채팅·변경 기록·스냅샷 유지 → 닫은 뒤 남은 Excel 없음.

### 범위 밖

조건부 서식, 셀 안 부분 서식(리치 텍스트), 이미지·차트·도형·메모, 여러 시트를 한 번에 취합, 사외(인터넷) 접속·HTTPS·로그인,
자동 업데이트. 아직 하지 않은 것: 호스트가 그리드에서 직접 입력, 참여자 행 추가.
