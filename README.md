# 엑셀 취합 도구 (merge-master)

호스트가 Excel(COM)에서 시트를 불러와 취합용으로 설정하고, 앱 안의 웹 서버를 열면 사내 LAN의 참여자들이
브라우저로 접속해 동시에 입력합니다. 마지막에 호스트가 결과를 다시 엑셀로 저장합니다.

- 화면 기준: [`design/취합 협업 와이어프레임.dc.html`](design/) (1a~1i)
- 단계별 계획: 0단계 골격·스파이크 → 1 COM 불러오기 → 2 취합 설정·그리드 → 3 서버·접속 → 4 동시 편집 → 5 엑셀 저장(MVP) → 6 모니터링·히스토리·소통 → 7 안정화·배포 → 8 여러 시트 함께 취합 → 9 여러 업무 동시 진행 → 10 에이전트 PC에서 서비스

## 구조

```
apps/host/            호스트 UI (Tauri 웹뷰, React)
apps/participant/     참여자 웹 (React) → 빌드 결과를 collect-server가 바이너리에 포함
packages/grid/        공용 가상 그리드 (병합·틀 고정·Excel 서식)
packages/chat/        두 앱 공용 채팅 부품 (목록·리액션·셀블럭 칩·미리보기·입력 칸·'@ 셀 선택')
packages/shared/      ts-rs 생성 타입, 표시 형식 유틸, 두 앱·그리드 공용 색 토큰(tokens.css)
src-tauri/            Tauri 앱: command, 앱 상태
crates/excel-com/     Excel COM: 전용 STA 스레드, IDispatch 래퍼, 시트 읽기, 수식 계산 사본
crates/collect-core/  도메인 모델 (SheetModel·취합 설정·권한 엔진·입력 검사·저장 계획·이력 보기)
crates/collect-server/ axum HTTP/WebSocket 서버(포트 하나에 여러 업무) + 세션 액터 (+ collect-dev-server)
crates/collect-store/ 세션 저장소: SQLite(변경 기록·스냅샷 zstd)
crates/collect-excel/ Excel 스레드 작업 · 수식 재계산(계산 사본) — 호스트 앱
crates/agent-protocol/ 호스트 앱 ↔ 에이전트 관리 API 형식 · 넘길 묶음 · 호스트 앱의 HTTP 클라이언트(client 기능)
crates/collect-agent/ 에이전트(merge-master-agent.exe): 다른 PC의 트레이에서 서비스, 마감 때 엑셀로 저장
fixtures/             테스트용 시트 모델(JSON). 원본 xlsx는 scripts/make-fixture.ps1로 생성
e2e/                  Playwright (설치된 Chrome, 없으면 PW_EXECUTABLE에 Chromium 경로)
```

## 준비물

Windows 10/11, Excel(데스크톱), Rust stable(MSVC), Node 22+, pnpm 10.

```powershell
pnpm install
```

## 0단계 스파이크 결과

측정 PC: 이 개발 PC, Excel 16, 예산신청서 1,002행 × 9열(병합 443, 수식 1,000, 목록 유효성 1).

| 스파이크           | 목표                                                           | 결과                                                                               |
| ------------------ | -------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| A. COM 읽기 — 값   | < 1초                                                          | 8 ms (`Value2` 한 번)                                                              |
| A. COM 읽기 — 서식 | < 10초                                                         | 0.9초 (분할 정복, 블록 197개 탐색 → 서식 9종)                                      |
| A. COM 읽기 — 전체 | –                                                              | 1.9초, Excel 호출 6,688회 (병합 0.9초가 가장 큼)                                   |
| B. 서버            | 다른 브라우저 간 WS 브로드캐스트, 열린 연결이 있어도 정상 종료 | 통과 (단위 테스트 + E2E). Tauri 앱 안에서 LAN 주소로 서빙 확인 (`pnpm smoke:host`) |
| C. 그리드          | 1,000행 스크롤 60fps 근접                                      | 평균 59fps, p95 17ms, 동시에 그린 셀 최대 287개                                    |

확인된 사항

- Excel 개체 모델은 같은 멤버 이름에 같은 DISPID를 쓴다(`EXCEL_COM_VERIFY_DISPIDS=1`로 검증) → 이름 조회 캐시로 호출 수 절반.
- 한국어 Excel은 '일반' 표시 형식을 `G/표준`으로 돌려준다 → `Application.International(26)`으로 `General`로 정규화.
- PowerShell COM 바인더는 2차원 배열 대입에서 `InvalidCastException`을 낼 때가 있어 픽스처 스크립트는 리플렉션으로 설정한다.

남은 확인(사람이 해야 함)

- 다른 PC·휴대폰에서 `http://<호스트IP>:8080/`(업무 목록)·`http://<호스트IP>:8080/q4` 접속, Windows 방화벽 허용 대화상자 동작(처음 서비스를 열 때 Windows가 묻는다).

## 1단계: 엑셀 불러오기 (1a)

시트를 고르면 **사전 감지**(값·수식 전체 + 위쪽 21행의 병합·굵게만 읽음, 예산신청서 0.3초)로 범위·틀 고정을
채우고 곧바로 전체를 읽어 미리보기를 보여 준다. **머리글 행은 기본 없음**이다(감지가 틀리기 쉬워 사용자가 '머리글 행'의 끝 행을
적어 정한다 — 끝 행 칸이 비어 있으면 '없음', 비우면 다시 없음). 범위·가져올 항목을 고치면 입력이 멈춘 뒤 다시 읽고(앞선 읽기는 취소),
머리글 행 수·틀 고정 열은 다시 읽지 않고 미리보기에 바로 반영한다. '불러오기 → 취합 설정'을 누르면 그 상태로 확정된다.

시트 목록은 체크 목록이라 **여러 시트를 함께** 고를 수 있다(처음엔 활성 시트만, 8단계 참고). 시트 이름을 누르면 그 시트를 미리 보고
범위·머리글·틀 고정·가져올 항목은 시트마다 정한다. 미리보기 머리의 '⤢ 크게 보기'는 창 가득한 모달로 같은 미리보기를 보여 주고
(머리글 행 수·틀 고정 열을 그 자리에서 바로 고침, Esc·바깥 클릭으로 닫기), 시트를 여럿 고르면 미리보기·모달 아래에 시트 탭이 생긴다.

**숨긴 행·열은 펼쳐서 불러온다**: Excel에서 숨겨져 있던 행·열(자동 필터·개요로 숨긴 것 포함)은 기본 크기(행 15pt, 열 48pt)로
펼쳐 읽고(`SheetModel.unhiddenRows`·`unhiddenCols`), 참여자에게도 보인다(필요하면 1b에서 잠근다). 저장할 때 Excel에서도 숨김을 풀고
그 크기로 맞춘다(저장 화면 '숨김을 풀 행·열 N줄' — '서식 반영' 옵션과 상관없이). 계산 사본도 펼쳐 `SUBTOTAL(10x)` 같은 결과가 저장
파일과 같다. 예전의 '숨긴 행·열 포함' 선택은 없앴다.

**배경색**(`excel-com` `probe_fill`): 단색은 그 색, 무늬 채우기(12.5% 회색·빗금 …)는 배경색 위에 무늬색을 무늬가 덮는 만큼 섞은 단색
('자동' 배경은 흰색, '자동' 무늬는 검은색), 그라데이션은 색 지점들의 평균이다. Excel이 색이 아닌 값(음수·범위 밖)을 돌려주면 검은색
대신 채우기 없음으로 둔다(예전에는 무늬 칸의 '자동' 배경이나 이런 값이 검은색으로 보였다). 앱에서 서식을 바꾼 칸을 저장하면 앱에서
보인 그 색을 단색으로 쓴다.

감지 규칙 (`crates/collect-core/src/detect.rs`, Excel 없이 단위 테스트)

- 표 범위: 아래·옆의 빈 행·열을 자르고, 위쪽의 빈 행·제목 행(내용 1칸)·안내 행(표 너비 절반 미만)을 건너뛴다.
- 머리글: 첫 행이 모두 글자면 머리글. 그다음 행은 위 머리글의 세로 병합에 걸쳐 있거나, 모두 글자이면서 굵게/가로 병합이면 머리글.
  감지값은 배정 기준 열 후보를 찾는 데 쓰고, 1a 머리글 행의 기본값으로는 쓰지 않는다(기본 없음).
- 열 이름: 가장 아래 머리글 행부터 위로 올라가며 처음 보이는 글자(병합 고려).
- 배정 기준 열 후보: 머리글 낱말(담당·작성자·이름…), 사람 이름 모양(한글 2~4자, 팀·부·비 등으로 끝나지 않음), 반복 여부로 점수.

Excel에서 확인한 함정

- 여러 행 범위의 `EntireRow.Hidden`은 섞여 있어도 Null이 아니라 False → 숨김은 행 높이·열 너비 0으로 판정한다(펼칠 줄을 고를 때).
- `Window.SplitRow/SplitColumn`은 창이 작으면 '보이는 칸 수'로 줄어든다(앱이 띄운 숨은 Excel 창에서 실제로 발생) →
  스크롤 창을 1행·A열로 보내 Excel이 막아 준 위치를 읽고 되돌린다.
- 비활성 시트의 틀 고정은 화면 갱신·이벤트(VBA `Worksheet_Activate`)를 끄고 잠깐 활성화해 읽은 뒤 원래 시트·통합문서로 되돌린다.
- '파일 열기'는 이미 열린 파일이면 그 문서를, 실행 중인 Excel이 있으면 그 Excel을(사용자에게 보임), 없으면 숨은 인스턴스를 쓴다.
- Excel이 닫히면(RPC_E_DISCONNECTED 등) '다시 찾기' 안내, 바쁘면(편집 중인 셀·대화상자) 8초 재시도 후 안내, 100만 셀 초과 범위는 읽기 전에 거절.

## 2단계: 취합 설정 (1b)

불러온 시트를 확정하면 설정 초안이 만들어지고(`CollectConfig::suggest`), 호스트가 1b 화면에서 고친다. 위쪽 탭으로
**열 역할**과 **담당자 배정**을 나눠 다룬다. 담당자 배정은 기본으로 비어 있다(행 배정 없음).

- **열 역할 탭**: 범위를 고르고(드래그·Shift·열/행 머리글 클릭) 위쪽 역할 줄의 `[입력 | 잠금]` 중 하나나 조회조건을 누른다 —
  열 역할·조회조건은 **이 줄에서만** 바꾼다. `[입력 | 잠금]`은 칸 하나만 골라도 **고른 열 전체**의 역할을 바꾸고(셀 예외는 건드리지
  않음), 고른 열의 지금 역할이 그 역할 색으로 눌려 보인다(섞여 있으면 둘 다 꺼짐). 조회조건은 고른 열이 모두 조회조건이면 '켬',
  일부만이면 '일부'(점선, 누르면 모두 켬)로 보인다. 칸 단위 입력 가능·입력 금지는 오른쪽 **셀 예외**(종류를 고르고 '+ 선택 셀을
  예외로')에서만 정한다. 오른쪽(위에서부터): 열 속성(지금 역할·조회 표시, **필수는 입력 열일 때만** — 잠그면 필수도 꺼진다,
  형식·단위·목록 항목·안내), 참여자 권한(서식 변경 불가/배경색만/허용, 남의 행 읽기 전용/숨김/편집 가능(담당자 열은 '내 행' 필터용
  표시일 뿐 입력 영역이면 누구나 입력), 크기 조절 금지/허용, 수식 칸(값으로 바꾸기 — 기본 / 잠금)), 셀 예외(메모). 그리드 아래에는
  범례 없이 그리드만 보인다.
- **담당자 배정 탭**: 위쪽 첫 줄은 행 배정 기준 열(기본 '행 배정 없음', 담당자 이름 열 후보 1순위는 '(추천)'), 둘째 줄은
  고른 칸의 담당자('선택 셀 담당자' 이름 — 명단과 IP 명단의 이름을 고르거나 입력 — · 메모 · '선택 범위 배정').
  오른쪽: 명단(이름 추가·빼기), 범위 배정 목록.
- **그리드 아래(두 탭 공통)**: 오른쪽에 **'참여자가 새 행을 추가할 수 있게 하기'** 스위치(시트마다, 새 업무는 켬)만 있다. 행 삭제
  권한은 따로 없다 — 참여자는 자기가 추가한 행을 늘 지울 수 있고, 호스트는 1b·1d 오른쪽 클릭 메뉴로 지운다. 참여자 조회조건은
  늘 켜져 있다(예전의 '필터·정렬' 권한은 끄는 곳이 없다).
- **칸 편집**: 그리드에서 칸을 두 번 누르거나 바로 입력(한글 첫 글자 포함)·F2로 고치고 Enter/Tab으로 확정, Delete는 고른 범위를 지운다.
  머리글(열 이름)·잠금 칸·**수식 칸**도 고칠 수 있고 병합에 덮인 칸은 못 고친다. 수식 칸에 값을 넣으면(같은 값이어도 확정하면) 수식 대신
  그 값이 들어간다(`=`로 시작해도 글자 — 수식으로 넣을 수는 없다, 고치기 시작하면 안내). 데이터 칸은 열 형식에 맞으면 그 값(숫자·날짜·목록 항목)으로,
  아니면 글자 그대로 넣는다. 참여자 입력처럼 버전·이력(호스트 이름)·진행률에 반영되고 참여자에게 간다
  (command `sheet_set_cells`). 머리글·행 배정 기준 열을 고치면 열 이름·명단을 다시 계산한다.
- **크기 조절**: 열 머리글 오른쪽 끝·행 머리글 아래 끝을 끌면 너비·높이가 바뀐다(`FormatEdit::ColWidth`·`RowHeight`, pt, 숨긴 줄은
  그대로). 머리글로 여러 열(행)을 골라 두고 그중 하나를 끌면 고른 것 모두 같은 크기가 된다(필터·참여자 시점으로 숨은 행은 건너뜀).
  4 모니터링 그리드에서도 같다. 참여자 화면에도 바로 보인다 — 권한이 그대로라 새 시트를 다시 보내지 않고 바뀐 크기만 알린다
  (`resized`, 호스트 화면은 `HostEvent::Resized`). 참여자는 참여자 권한 **크기 조절**(기본 금지)을 허용하면 같은 방법으로 바꿀 수 있고,
  바꾸면 모두에게 보인다(`resize`, 마감·읽기 전용이면 거절, '남의 행 숨김'이면 내게 보이는 행만).
  머리글을 **오른쪽 클릭**해도 바꾼다: 볼륨처럼 끄는 슬라이더(열 5–400pt, 행 5–200pt)와 값 입력(pt, 열 2–1000·행 2–409, Enter·칸
  벗어남에 적용). 누른 머리글이 지금 선택 밖이면 그 열(행) 하나를, 선택 안이면 고른 것 모두를 바꾼다(1b·1d·참여자 화면 같음).
- **오른쪽 클릭 메뉴(1b·1d)**: 크기 조절과 함께 **표 맨 아래에 행 추가**, **표 맨 오른쪽에 열 추가**(입력 열·글자, 왼쪽 열 서식·너비를
  따름), **취소 행 표시/풀기**, **행 삭제·열 삭제**. **행은 엑셀에서 불러온 행도 지운다**(수식 칸이 있어도) — 저장할 때 Excel에서도 그
  행 전체(표 밖 칸 포함)를 지운다(메뉴에서 'N개는 저장할 때 Excel에서도 지웁니다'로 한 번 더 묻는다). 머리글 행, 병합의 첫 행만 지우는 경우
  ('병합된 행을 모두 함께 지우세요'), 담당자가 배정된 행(행 배정 기준 칸에 이름이 있거나 범위 배정이 걸침)은 지우지 않는다. 열은 앱에서
  추가한(기준 시트에 없는) 열만, 행 배정 기준 열·범위 배정이 걸친 열은 빼고 지운다(메뉴에 까닭, 세션도 같은 규칙으로
  `collect_core::structure`가 다시 검사). 값이 있는 칸이 있으면 메뉴 안에서 한 번 더 묻는다. Excel로 저장하는 동안에는 행·열을 지우지
  않는다(기준 시트가 저장하는 파일과 어긋나지 않게). 명령 `sheet_structure`(`StructureEdit`).
- 1a 미리보기·1b 그리드는 가로·세로로 스크롤된다(스크롤바는 늘 보인다).
- **서식 도구 줄**: 글꼴·크기·굵게·기울임·밑줄·글자색·채우기·테두리(모두/바깥쪽/없음)·병합/해제·맞춤.
  채우기 옆 **색 코드 칸**에 고른 칸의 채우기(`#ff00ff`, 없으면 비어 있음)가 보인다. 코드를 복사해 다른 칸을 고르고 붙여넣으면
  바로 그 색으로 칠하고, 직접 고쳐 Enter·칸 밖으로 나가도 칠한다(`#f0f`처럼 세 자리, `#` 없이도 받음).
- **참여자 시점으로 보기**: 명단의 한 사람으로 보면 남의 행은 회색(또는 '숨김'이면 사라짐), 내 칸만 흰색이다.

권한 규칙 (`crates/collect-core/src/access.rs`)

- 입력 가능 = (배정 행 ∪ 배정 범위 ∪ 담당자 없는 칸) ∩ 입력 영역 − 입력 금지 − 머리글 − 병합에 덮인 칸(참여자 권한 '수식 칸'을
  잠금으로 바꾸면 − 수식). 수식 칸은 필수로 세지 않는다.
- **수식 칸**: 값을 넣으면(참여자·호스트·행 추가한 사람 모두) 그 칸의 수식을 버리고 값으로 둔다 — 그 뒤로는 다시 계산하지 않고, 저장할 때
  Excel에도 값으로 쓴다(기준 시트에서 수식이던 칸은 값이 같아도 쓴다, 원본 변경 감지에서 충돌로 보지 않는다). 기록을 다시 읽어도 수식은
  되살아나지 않는다. 수식 재계산 결과는 기록되지 않으므로 이 규칙과 섞이지 않는다.
- **담당자 없는 칸은 누구나**: 행 배정(기준 열 이름)도 범위 배정도 걸리지 않은 입력 칸은 명단의 누구나 입력한다(행 배정 없이
  열 역할만 정하면 모두가 모든 입력 칸을 쓴다). '남의 행 숨김'이어도 이런 행은 모두에게 보인다. 담당자별 진행률에는 들지 않고
  '담당자 없는 필수 N칸(누구나 입력)'으로 따로 센다.
- 셀 예외는 열 역할을 덮어쓰고, 같은 칸이면 **입력 금지가 항상 우선**한다. 범위 배정은 행 담당자의 권한에 더해진다(둘 다 입력 가능).
- 명단 = 행 배정 기준 열의 이름(병합 고려, 나온 순서) + 직접 추가한 이름 + 범위 배정 받은 이름.

기본 제안 규칙: 제목은 엑셀 파일 이름(확장자 제외), 행 배정 기준은 정하지 않음. **처음엔 모든 열이 입력**이고 잠글 열은 호스트가
직접 정한다(수식 칸은 열 역할대로 — 입력 열이면 값으로 바꿀 수 있다). 거의 다 채워진 글자 열 중 값이 2~50가지로 반복되는 열(수식 열·배정 기준
후보 열 제외)은 조회조건, 목록 유효성은 목록 형식, 숫자 열은 숫자 형식(머리글 괄호 안을 단위로: `금액 (천원)` → 천원).

설계 결정

- 판정은 **Rust 한 곳**에서 한다. 화면은 셀당 1바이트 상태(`ConfigView.flags`, base64)를 받아 그리기만 하므로 1b 화면·참여자
  시점 미리보기·3단계 서버(`project`)가 같은 규칙을 쓴다. 상태 비트 값은 `packages/shared/src/flags.ts`와 Rust `access::flag`가 같아야 한다.
- 서식 도구 줄·크기 조절의 변경은 앱 안의 시트에 반영되어 참여자에게 보인다. 저장할 때 '앱에서 바꾼 서식·병합·크기도 반영'을 켜면
  Excel에도 쓴다(5단계).

## 3단계: 협업 서버와 접속 (1c · 1e)

구조: **세션 액터**(`crates/collect-server/src/session/`) 하나가 시트·설정·권한 엔진·참여자·승인 대기를 소유한다.
WebSocket 연결과 호스트 명령은 채널로 명령만 보내고, 호스트 화면(1c 접속자 표)은 `watch` 스냅샷을 Tauri 이벤트(`participants`)로 받는다.
(4단계부터 세션이 시트·설정의 유일한 주인이다 — 아래 4단계 참고.)

접속 흐름(프로토콜 v1, `protocol.rs`)

- **IP 명단**(1c 아래 — 처음엔 머리 줄(명수·JSON 단추)만 보이게 접혀 있고 누르면 펼친다, 앱 설정 폴더의 `ip-names.json`, 모양 `{"192.168.0.11": "이서연"}`): 명단에 있는 IP에서 열면 연결하자마자
  `known{name}`을 받고 이름을 묻지 않고 그 이름으로 바로 입장한다(명단에 없던 이름이면 명단에 더한다). 1c에서 IP·이름을 더하고
  고치고 빼며, JSON 파일로 **내보내고 불러온다**. 승인할 때 'IP 명단에 저장'을 켜면 그 IP를 명단에 넣는다.
- **명단 밖 IP**: 이름을 입력하면 명단에 있는 이름이어도 `pending` → 호스트가 '배정 후 승인'(범위 지정 가능)하거나 '거부'.
  같은 이름이 다른 기기에서 접속 중이면 승인할 때 앞 기기는 `kicked(switchedDevice)`.
- 같은 IP(같은 PC의 다른 창)에서 같은 이름이 접속 중이면 `dupName` → '이 기기로 전환'(`switchDevice`, IP 명단의 이름만).
- **호스트 이름**: 호스트 PC의 IP가 IP 명단에 있으면 그 이름(없으면 1c의 '내 이름')이 접속자 목록·공지·채팅·변경 기록에
  보인다. 채팅에는 '호스트'라고 붙이지 않고 이름만 보인다(참여자 쪽 '박지훈 님에게만').
- 입장하면 재접속 토큰을 받아 브라우저(`localStorage`, 주소 경로별)에 둔다. 새로 고침·연결 끊김 뒤에는 토큰으로 이름 입력·승인 없이
  다시 들어온다. 토큰은 기록 파일에도 남아(블롭 `people`) 앱을 다시 켜도 다시 승인받지 않는다. 호스트가 연결을 끊으면 다시 승인받는다.
- 시트는 입장한 뒤에만, **그 사람 기준**(`project`)으로 보낸다. '남의 행 숨김'이면 남의 행 값은 보내지 않는다. `/api/sheet`는 없앴다.
- 프레즌스: 접속 중 / 자리 비움(3분 무활동) / 미접속, 다른 사람 커서는 이름표로 보인다.

호스트 1c: **서비스 위치**(이 PC / 에이전트 PC — 10단계)·업무명(취합 제목, 기본은 엑셀 파일 이름)·내 이름(필수 — 비어 있으면 빨간 테두리이고 공유를 시작할 수 없다, 설정의 `requester`.
비어 있을 때 이 PC의 IP가 IP 명단에 있으면 그 이름으로 저절로 채워 저장한다)·안내·마감(**호스트 PC 시각 기준**, 옆에 지금 시각), 네트워크·포트(모든 업무 공통)·주소 경로, 접속 주소·업무 목록 주소·안내문 복사, '마감 시각이 되면 (읽기 전용으로 전환 / 공유 닫기)',
접속자 표(상태·배정 요약·현재 위치·필수 진행률·연결 끊기).

**입력 마감 고르기**: 날짜 칸(달력으로만 고른다 — 키 입력은 막는다) + 시(00~23시)·분(5분 단위) 고르기. 키보드로 시·분을 칠 수 없고,
날짜·시·분이 모두 정해졌을 때만 저장한다(고치는 도중에 마감이 지워지지 않는다 — 예전에는 칸을 지우는 순간 빈 값이 저장되어 마감이
사라졌다). 날짜를 처음 고르면 18:00이 채워진다. 지우기는 '마감 지우기'로만(에이전트 PC에서는 마감이 필수라 없다). 5분 단위가 아닌 예전
값(예: 18:07)은 그 분을 선택지에 더해 그대로 보인다.

개발 서버: `pnpm dev:server`는 `--dev-admin`으로 `/__dev/approve|reject|kick|snapshot|ip-names`를 켠다(앱에는 없음, E2E용).
`--others-hidden`, `--required F,H`, `--locked A,B`(호스트가 1b에서 하듯 그 열을 잠근다 — 처음엔 모든 열이 입력), `--title`,
`--requester`, `--add-rows`(참여자 행 추가 허용), `--ip-names <JSON 파일>` 옵션이 있다. `pnpm dev:server`와 E2E는 예산신청서
A~E·G열(인력계획 A~D열)을 잠가 띄운다. `--fixture`를 여러 번 주면 그 시트들을 함께 취합하고, `--required 2:E`·`--locked 2:A`처럼
`시트 번호:열`로 둘째 시트부터의 열을 정한다.
`--session hr --fixture … --title …`은 같은 포트에 업무를 하나 더 연다(9단계). 업무가 여럿이면 관리 API는 `?s=<주소 경로>`로 고른다.
IP 명단이 없으면 모두 이름 입력 + 승인이다(E2E는 `/__dev/approve`로 승인한다). `--auto-approve`는 에이전트 PC처럼 자동 승인으로 띄운다
(E2E `auto.spec.ts`, 포트 8095).

**자동 승인**(프로토콜 v9, 에이전트 PC에서 서비스할 때 — 10단계, `SessionInfo.autoApprove`): 관리자가 승인하지 못할 수 있어, IP 명단 밖 사람도
**입력한 이름 그대로** 바로 들어온다(명단에 없던 이름이면 명단에 더한다, 로그 '자동 승인: 이름 (IP)'). 참여자 첫 화면에 '이름을 입력하면
바로 참여합니다(본인 이름을 정확히…)'. 이렇게만 기다린다(`pending.reason`):

- `online` — 같은 이름이 다른 기기에서 접속 중(자동으로 끊지 않는다). 그 연결이 끊기면 바로 들어온다('다른 기기에서 ‘X’(으)로 접속 중입니다…').
  호스트가 승인하면 앞 기기는 끊긴다.
- `approval` — 호스트가 끊었거나 거절한 이름(기록 파일 메타 `held`, 승인하면 풀린다), 또는 새 이름이 300명을 넘음.

어느 모드든 호스트가 연결을 끊으면 그 사람의 재접속 토큰을 새로 만든다(끊긴 사람이 옛 토큰으로 바로 다시 들어오지 않는다).

## 4단계: 동시 편집 (1f · 1g)

**세션 구조**: 업무에서 시트를 확정하면 세션이 생기고(`SessionHandle::spawn`) 그 업무를 끝낼 때까지 산다(9단계 — 업무마다 세션 하나).
공유 시작·중지는 그 세션을 참여자 서버의 업무 목록(`Hub`)에 넣었다 뺄 뿐이라, 멈췄다 다시 열어도 입력한 값·이력·진행률이 그대로다. 호스트(1b·1c)는
`session.with(|s| …)`로 세션 안에서 시트·설정을 읽고 고친다(설정을 고치면 `s.changed()` → 권한 재계산 + 접속자에게 새 시트).
다시 불러와 확정하면 `s.replace()`로 셀 버전·잠금·이력을 새로 시작한다.

**셀 수정**(프로토콜 v2, `setCells{batch, cells:[{row,col,value,base}]}`): 서버가 칸마다 권한 → 마감 → 남의 편집 잠금 →
형식 검사·정규화(`collect_core::validate`, 화면도 같은 규칙의 TS판 `packages/shared/src/validate.ts`로 즉시 검사) → 적용·버전 증가 →
이력(`ChangeEntry`) 순으로 처리한다. 보낸 사람에게는 `applied`(정규화한 값·새 버전·거절 칸과 이유·충돌 칸), 다른 사람에게는
`cells`를 보낸다('남의 행 숨김'이면 그 행이 보이는 사람에게만). 필수 진행률은 다시 세지 않고 증분으로 고친다.

- **충돌**: `base`가 지금 버전보다 낮고 마지막으로 바꾼 사람이 내가 아니면 나중 입력(내 값)으로 덮어쓰고 '충돌 칸'으로 알린다.
- **편집 잠금**: 편집기를 열면 `lock`, 확정하면 서버가 풀고 취소하면 `unlock`. 한 사람은 한 칸만 잠근다. 연결이 끊기면 30초 유예
  (다시 붙으면 이어서), 10분 넘게 잡고 있으면 풀린다(편집기는 1분마다 다시 잡음). 호스트는 1c ⋯ 메뉴 '편집 잠금 해제'로 즉시 푼다.
- **마감**: 마감 시각은 **호스트 PC의 현지 시각**으로 잰다(1초 주기 점검). 마감 동작이 '읽기 전용으로 전환'(기본)이면 그 순간 모두에게
  `readOnly` → 입력·잠금 거절, '공유 닫기'면 그 순간 한 번 `HostEvent::DeadlineClose` → 호스트 앱이 이 업무의 공유를 닫는다(참여자는
  `closing{deadline}` → '마감 시각이 지나 공유가 닫혔습니다', 다시 열리면 이어서 붙는다). 같은 마감 시각으로는 한 번만 닫고(메타
  `deadlineFired`), 호스트가 다시 공유하면 그대로 둔다. 호스트가 마감을 지난 시각으로 옮겨도 바로 알린다. 공유를 닫으면 호스트 화면도
  '공유 전'으로 바뀌고(위쪽 상태·1c·1d, 알림) 필요하면 1c '공유 시작'으로 다시 연다. 예전 설정의 '마감 후 자동
  읽기 전용 끔'은 '읽기 전용으로 전환'으로 읽는다.
- **호스트 시각**: `welcome.serverNow`·`pong.now`(호스트 PC 시각)로 참여자 기기 시계와의 차이를 잡고, `session.deadlineAt`(호스트가
  자기 시간대로 계산한 마감 시각, 유닉스 ms)과 비교한다. 참여자 기기 시계가 틀리거나 시간대가 달라도 호스트와 같은 남은 시간이 보인다.
- **같은 묶음 다시 보내기**(오프라인 대기열 재전송)는 한 번만 반영한다(`이름 + 묶음 ID`).
- **서식**: 참여자 권한이 '배경색만'·'허용'일 때만, 내가 입력할 수 있는 칸에만(`format` → 모두에게 `styles`, 병합에 덮인 칸은 머리 칸을
  따른다). 채우기는 연한 노랑·초록·파랑·분홍 + 빨강 `#ea2a2a`·진한 노랑 `#ffff00`·진한 파랑 `#0000ff`, '허용'이면 글자색(검정·빨강·
  진한 파랑·진한 노랑·회색)과 맞춤(왼쪽·가운데·오른쪽, 다시 누르면 일반)·굵게·기울임도 쓴다.
- **구조 판**(`model.layout`): 앱에서 붙인 행·열을 지울 때마다 오른다. 참여자는 `setCells`·`lock`·`format`·`deleteRows`·`cancelRows`에
  본 판을 실어 보내고, 서버는 다른 판에서 온 것을 받지 않는다('표 구조가 바뀌어 반영하지 못했습니다' — 오프라인 대기열이 밀린 칸에
  쓰지 않게). 새 판을 받으면 참여자는 되돌리기 기록을 비운다(표 끝에 행·열이 붙는 것은 좌표가 그대로라 남긴다).
- **크기 조절**: 참여자 권한 '크기 조절'이 '허용'일 때만 열·행 머리글 경계를 끌어 너비·높이를 바꾼다(`resize` → 모두에게 `resized`,
  프로토콜 v6). 머리글로 여러 열(행)을 골랐으면 모두(숨은 행은 건너뜀). 머리글 오른쪽 클릭 메뉴의 슬라이더·값 입력으로도 바꾼다.

**수식 재계산**(`excel_com::calc`, `src-tauri/src/recalc.rs`): 확정할 때 원본을 `SaveCopyAs`로 임시 파일에 복사해 **별도의 숨은
Excel**에서 연다(매크로·이벤트 끔, 계산 수동). 참여자 입력을 300ms 모아 사본에 쓰고 `Calculate` 뒤 수식 칸을 한 번에 읽어
바뀐 칸만 보낸다(`cells`, `by: ""`). 원본은 저장 전까지 건드리지 않는다. 사본을 열 수 없거나 Excel이 닫히면 1c에 '저장할 때 계산'으로
표시하고 취합은 계속한다. 글자는 `'`를 붙여 써서 숫자·수식으로 바뀌지 않게 한다. 사본은 1a 통합문서 목록에 보이지 않는다.

**참여자 그리드(1f)**: 방향키·Enter·Tab(병합·숨긴 행 건너뜀), 입력하면 바로 편집(Excel '입력' 모드: 방향키로 확정+이동),
F2·더블클릭은 '편집' 모드, Esc 취소, Alt+Enter 줄바꿈(그리드에서도 줄을 나눠 보이고, 다 보이도록 행 높이를 늘린다 — 최대 8줄,
Excel 원본 행 높이는 그대로), Delete 범위 지우기, Backspace, Ctrl+Z/Ctrl+Y(내 변경만, 묶음 단위 —
그 뒤 남이 바꾼 칸은 건너뜀), Excel 복사·붙여넣기(TSV, 한 칸을 범위에 붙이면 채우기, 형식이 틀리거나 남의 칸은 건너뛰고 알림),
목록 칸은 ▾ 또는 Alt+↓로 드롭다운. 잠긴 칸은 자물쇠 + '이서연' 이름표와 '끝나면 알려 주기'. 조회조건(호스트가 지정한 열)·내 담당만·
필수 미입력만 필터(걸 때 한 번 계산해 입력하는 동안 행이 사라지지 않음, 걸러진 행은 높이 0 → 병합은 보이는 행으로 다시 그림).
조회조건 콤보는 펼치면 **검색 칸**과 체크 목록이 있고 **여러 개를 고른다**(고른 값 중 하나면 보임, 누를 때마다 고르거나 빼고 목록은 열린 채,
단추는 '재무팀 외 2'). 그 열에 빈 칸인 행이 있으면 목록 맨 끝에 **'(빈칸)'** 항목이 생겨 빈 칸인 행만 고를 수 있다(1d 조회조건도 같다). 부분 일치 검색, ↑↓·Enter(고르기/빼기)·Esc, 맨 위 '전체'(조건 풀기) — 검색어가 있으면 '검색 결과 모두 선택'. '내 담당만'은 **'(담당자 없는 행 포함)'**으로
보인다(담당자 없는 행은 누구나 입력하므로 함께 남는다). 호스트가 담당자를 배정하지 않은 시트(행 배정 기준 열·범위 배정 없음,
`SheetView.assigned`)에서는 '내 담당만'을 숨긴다.
상태 바: 실시간 동기화 / 저장 중(0.4초 넘게 기다릴 때만) / 오프라인(대기 N건), 내 변경 수, 마지막 저장 시각, 편집 중인 칸. 다른 사람이
바꾼 칸은 그 사람 색으로 1.2초 물들고, 입력할 수 없는 칸에 쓰려 하면 내 담당 칸이 두 번 깜빡인다. 연결이 끊기면 그리드 위 띠로도
알린다(대기 건수, 다시 연결되면 2초 동안 '다시 연결되었습니다').

- **낙관적 반영**: 입력은 바로 그리고 답이 오면 서버 값으로 바꾼다. 답을 기다리는 칸(파란 모서리)은 남의 수정이 와도 내 값을 보인다.
- **오프라인 대기열**: 보내지 못한 묶음은 IndexedDB(주소 경로·이름별)에 두고, 다시 들어오면(새로 고쳐도) 처음 본 버전과 함께 보낸다.
- **한글 입력**: 활성 칸에 투명 편집기를 미리 놓아 두어 첫 글자부터 조합을 받는다(포커스가 옮겨지기 전에 그리드로 온 첫 글자도 받음).

**오른쪽 사이드바**: 위쪽 '☰ 사이드바' 버튼 하나로 열고 닫는다(안 읽은 알림·채팅 수 표시, 넓은 화면은 처음부터 열림, 주소 경로별로
기억). 왼쪽 경계를 끌어 너비를 바꾼다(260–720px, 그리드 쪽은 360px 남김, 두 번 누르면 기본 310px, 키보드 ←/→, 주소 경로별로 기억). 탭은 **셀 내용**(고른 칸의 위치·열 이름·필수/형식/내가 입력·안내·잠금 상태와 내용 전체 — 칸이 작아 안 보이는 긴 글·여러 줄을
여기서 보고 고친다. 고치기 시작하면 그 칸을 잠그고, 칸을 벗어나거나 Ctrl+Enter로 저장, Esc 취소. 고치다 그리드의 다른 칸·시트를 누르면
고치던 칸에 저장한다(형식이 틀리면 취소하고 알림, 누른 칸에는 넣지 않는다). 목록 칸은 드롭다운), 알림(공지·강조
메모는 적은 그대로 줄을 나눠 보임), 채팅(Enter 보내기, Shift·Ctrl+Enter 줄바꿈, 남의 글에 리액션, `@`로 셀 선택), 셀 이력.
브라우저 기본 오른쪽 클릭 메뉴는 띄우지 않는다(그리드 메뉴가 없는 곳에서 헷갈리지 않게 — 글 입력 칸에서는 붙여넣기 등에 쓰도록 둔다). 그리드 위의 셀 정보 줄(주소·fx)은 없앴다. 마감이 있으면 머리줄 오른쪽 위에 마감 시각(호스트가 정한 시각 그대로)과
**호스트 PC 시각 기준** 남은 시간(분은 올림 — 마감 시각 전에 '마감 지남'이 먼저 보이지 않게, 1분 안쪽은 초, 2분 안쪽은 1초마다·그 밖은
15초마다 갱신, 1시간 안쪽·마감 지남은 경고색)이 보인다.

**행 추가**: 1b 그리드 아래 스위치 '참여자가 새 행을 추가할 수 있게 하기'(새 업무는 켬)가 켜져 있으면 **보이는 마지막 행 번호칸 바로 아래에 ＋ 아이콘**이 생긴다
(행 단위 입력은 행 목록 아래 단추, 행 번호 오른쪽 클릭 메뉴에도 있다, `addRows`). 표 맨 아래에
마지막 데이터 행을 본뜬 빈 행을 붙인다(칸 서식·행 높이를 따르고, 수식 칸은 수식을 한 행씩 내려 쓰며 값은 저장할 때 계산).
행 배정 기준 열이 있으면 그 칸에 추가한 사람 이름을 넣어 그 사람의 행이 되고(기록 출처 '행 추가'), 없으면 담당자 없는 행(누구나)이다.
새 행은 잠금 열이어도 수식 칸 말고는 입력할 수 있다(새 비목·설명을 적도록 — 셀 예외 '참여자가 추가한 행' 입력 가능, 행 배정
기준 칸만 입력 금지. 이어서 추가하면 예외 범위가 늘어나고, 호스트는 1b 셀 예외에서 보고 지울 수 있다).
모두에게 새 시트를 보내고(`welcome` + `rowsAdded`), 추가한 사람은 새 행의 첫 입력 칸으로 간다. 한 번에 20행, 저장 전까지 1,000행,
시트 100만 칸까지. 행은 표 끝에만 붙이므로 기존 칸의 좌표·버전·이력·잠금은 그대로다. 호스트도 1b·1d 오른쪽 클릭으로 행(담당자 없는
행)·열을 붙인다.

**행 삭제**: 따로 권한 없이 참여자는 행 번호를 오른쪽 클릭해 **내가 추가한 행**(수식 칸이 있어도)을 지운다(`deleteRows`, 값이 있으면
메뉴 안에서 확인, 남의 행·엑셀에서 불러온 행(내게 배정된 행이어도)·남에게 배정된 범위가 걸친 행은 비활성). 엑셀에서 불러온 행은
호스트가 1b·1d 메뉴로 지운다(저장할 때 Excel에서도 지운다고 한 번 더 묻는다). 지우면 아래 행이 당겨지고, 칸 버전·잠금·마지막 작성자·강조·커서·스냅샷도 새 좌표로 옮긴다.
엑셀에서 불러온 행은 기준 시트에서도 지우고 그 순간 기준 시트 좌표로 `baseline.deletedRows`(`RowCut`)에 차례로 남긴다 — 저장할 때 Excel에
같은 차례로 `EntireRow.Delete`하면 기준 시트와 정확히 맞는다. 계산 사본도 그 행을 지운다(판 번호를 올려 옛 판의 계산 결과는 버린다).
시트·기준 시트·이력은 기록 파일에 한 트랜잭션으로 남긴다(`SAVEPOINT` 묶음 — 어긋난 채 꺼지면 다음 저장이 엉뚱한 행에 쓰므로). 지운 칸의 변경 기록은 '삭제됨'(`ChangeEntry.gone`, 파일에도)으로 남고 되돌리거나 다시 적용하지 않는다. 모두에게 새
시트(`welcome`) + `rowsDeleted`.

**취소 행**: 툴바의 '취소 행' 토글(행 번호 오른쪽 클릭 메뉴에도)로 고른 행 전체를 취소 표시한다(`cancelRows`, 내가 입력할 수 있는 칸이
있는 행만, 호스트는 1b·1d 메뉴로 어느 데이터 행이든). 보이는 열 전체가 회색 바탕 + 가운데 줄 + 취소선으로 보이고(행 번호도), 그 행의
필수 칸은 진행률·필수 미입력에서 빠진다(`model.cancelledRows`, 권한 엔진이 `REQUIRED`를 주지 않는다). 다시 누르면 풀린다.

**행 단위 입력(1g)**: 내 담당 행 목록(검색, 전체/미입력 탭, 미입력 먼저), 이전·다음 미입력, 읽기 전용 값 요약 띠(빗금, 수식 포함),
형식별 입력(숫자+단위, 목록은 칩, 날짜, 글자), 즉시 검사, 칸을 벗어나면 자동 저장, 이 행 변경 이력, 같은 비목 비교, '그리드에서 이 행 보기'.

시험: 서버 단위 테스트(편집·검사·잠금 유예/만료·충돌·중복 묶음·마감·숨김 정책·이력·서식 정책·재계산 요청·교체) +
WebSocket 통합(서버를 멈췄다 다시 열어도 값 유지), Excel 통합(`calc_copy_recalculates_without_touching_original`),
TS 단위(검사·편집 상태·필터·붙여넣기·TSV), E2E 14개(`e2e/editing.spec.ts`), 호스트 스모크(입력 → 진행률, G열 재계산, 잠금 해제).
개발 서버 관리 API에 `/__dev/unlock`·`/__dev/config`(마감·마감 동작·서식 정책·행 추가·행 삭제·크기 조절)·`/__dev/formulas`(재계산 결과 흉내)가
더해졌다. 개발 서버도 마감 동작이 '공유 닫기'면 마감 시각에 그 업무의 공개를 멈춘다(`/__dev/publish`로 다시 공개).

알아 둘 것

- 개발 서버(release)는 참여자 웹을 **빌드할 때 바이너리에 넣는다**(rust-embed). 웹을 고친 뒤 이미 떠 있는 서버로 E2E를 돌리면
  옛 화면이 나온다 → 서버를 다시 빌드하거나 끄고 `pnpm e2e`.
- 디스크가 부족하면 `target/debug/incremental`(수 GB)을 지워도 된다(다시 만들어짐). `CARGO_INCREMENTAL=0`으로 빌드하면 쌓이지 않는다.

## 5단계: 엑셀로 저장 · 취합 마감 (6 저장·마감, MVP)

화면(와이어프레임에 없던 화면을 새로 정의): 한 열로 **저장 위치**(가장 앞) → **저장 옵션**(접힘) → **저장한 뒤에는?**(선택 카드) →
[저장하기]. 헷갈리지 않게 취합 요약(바뀐 칸·입력한 참여자·완료율)과 담당자별 미입력 표는 이 화면에서 뺐다. 저장 전 확인(충돌 칸)은
있을 때만 맨 위에 나오고, 입력 받는 중/마감됨 상태만 한 줄로 보인다.

- **저장 위치**: '다른 이름으로 저장'(기본 `원본명_취합_YYYYMMDD.xlsx`, 원본 폴더) — 원본을 `SaveCopyAs`로 복사해 **별도의 숨은
  Excel**에서 쓰고 저장한다(원본은 그대로). '원본 통합문서에 반영하고 저장' — 원본에 쓰고 `Save`(저장한 적 없는 새 문서·읽기 전용
  문서는 막음, Excel에서 저장하지 않은 변경이 있으면 함께 저장된다고 알림). 원본이 닫혔으면 저장할 때 다시 연다.
- **차례**: 지운 행 → 추가한 열 → 추가한 행 → 숨김 해제 → 병합·값·서식·크기. 지운 행은 `baseline.deletedRows` 차례대로
  `EntireRow.Delete`(표 밖 칸도 함께, 다른 수식의 참조는 `#REF!`가 될 수 있다), 결과에 '지운 행 N'. 원본 변경 감지는 지운 행만큼 맞춘
  범위(`source_rows`·`align_to_baseline`)로 비교한다. 원본에 반영하면 적용한 것만 기준에서 비우고(`adopt_saved`), 쓴 칸은 기준 시트에서도 값이 된다.
- **무엇을 쓰나**(`collect_core::export::plan`): 기준 시트와 값이 다른 칸만(지금 수식인 칸·병합에 덮인 칸은 빼고, 기준 시트에서 수식이던
  칸은 값으로 바꿨으면 같은 값이어도 쓴다). 추가한 행에서 지운 수식 칸은 `FillDown`으로 되살리지 않는다. 열마다 이어진 칸은
  `Value2` 배열 한 번으로(병합 머리 칸은 따로). 글자는 앞에 `'`를 붙여 `0012`·`=1+1`·`1-2`가 숫자·수식·날짜로 바뀌지 않게 한다
  (표시 형식이 `@`인 칸은 그대로). 날짜는 일련번호, 빈 값은 지우기.
- **추가한 행·열**: 앱에서 표 오른쪽에 붙인 열은 먼저 Excel 표 오른쪽에 그만큼 열을 끼워 넣고(`EntireColumn.Insert`, 서식은 왼쪽 열을
  따름) 너비를 맞춘다(`ColInsert`). 표 아래에 붙인 행은 Excel 표 끝에 그만큼 행을 끼워 넣고(아래 내용은 밀려 내려감, 서식은 위 행을
  따름) 높이를 맞춘 뒤, 위 행의 수식을 새 행까지 채워 내린다(`FillDown`, Excel이 상대 참조를 맞춘다). 기준 시트와의 비교는 (행, 열)로
  하고, 새 칸의 원래 서식은 Excel이 끼워 넣을 때 따르는 칸(마지막 열·마지막 행)의 것으로 본다. 원본에 반영하면 새 행·열이
  기준 시트에 붙는다(`adopt_structure`). 그사이 Excel 변경 감지는 원래 범위만 비교한다.
- **취소 행**: '취소 표시한 행: 취소선 + 회색 채우기'(취소 행이 있을 때 보임, 기본 켬)면 그 행의 표 안 칸에 취소선과 회색 채우기
  (`#D9D9D9`)를 쓰고, 원본에 쓴 뒤 취소를 푼 행은 원래 서식으로 되돌려 쓴다('앱에서 바꾼 서식' 옵션과 따로). 기준 시트의
  `cancelledRows`가 이미 Excel에 쓴 행이다.
- **함께 넣기**('저장 옵션'을 펼치면 보임): '변경 이력' 시트(기본 꺼짐; 시각·사용자·셀·항목·이전 값·새 값, 이름이 겹치면 `변경 이력 2`), 바뀐 칸 노란색 표시,
  앱에서 바꾼 서식(글꼴·채우기·맞춤·테두리)·병합·열 너비·행 높이 반영(바뀐 것이 있을 때만 보임). 행 높이는 `RowHeight`(pt)로,
  열 너비는 글자 단위 `ColumnWidth`라 지금 `Width`와의 비로 바꿔 쓰고 `Width`를 다시 읽어 맞춘다.
- 쓰는 동안 화면 갱신·이벤트·자동 계산·경고를 끄고 끝나면 되돌린다(되돌릴 때 수식이 다시 계산된 뒤 저장). 저장한 뒤 쓴 칸을 다시 읽어
  확인한다(결과에 '다시 읽어 확인함' 또는 다른 칸 수).
- **원본 변경 감지**(`export::compare`): 저장 직전에 불러온 범위를 다시 읽어, 쓸 칸 중 불러온 뒤 Excel에서 직접 고친 칸(충돌)을 보여 주고
  칸마다 '취합 값' / 'Excel 값'을 고르게 한다. 'Excel 값'을 고르면 그 칸은 쓰지 않고 취합 값도 Excel 값으로 바꾼다(참여자에게 알림,
  이력에 `Excel(원본)`). 취합하지 않는 칸이 많이 바뀌었으면(20칸 넘게, 비교한 칸의 20% 넘게) 행·열을 넣거나 지워 표가 밀린 것으로 보고
  '그래도 저장'을 확인해야 저장한다.
- **기준 시트**: 세션이 불러온 시점의 시트를 따로 들고 있다(`Shared::baseline`). 원본에 반영하면 쓴 값(과 서식)이 새 기준이 되어,
  다시 저장할 때는 그 뒤에 바뀐 칸만 쓴다. 다른 이름으로 저장은 기준을 바꾸지 않는다.
- **저장 뒤**(옵션에 숨기지 않고 아래쪽 선택 카드로 보임): 이 업무 공유 중지(**기본**) / 서비스 계속 / 읽기 전용으로 전환(취합 마감 — 참여자에게 '호스트가 취합을 마감했습니다', 입력·잠금 거절).
  사이드바에 '취합 마감됨'.
- **마지막 단계의 선택지는 둘**: **[저장하기]**와 **[저장 없이 업무 끝내기]**(저장하지 않은 변경이 있으면 확인 대화상자). 헷갈리던
  '저장 없이 취합 마감'은 없앴다. 저장 뒤 '읽기 전용으로 전환'으로 마감한 업무에만 '취합 다시 열기'가 보인다.

시험: collect-core 단위(바뀐 칸·블록·글자 보존·서식/병합·이력 표·충돌/표 밀림·요약), 세션 단위(기준·호스트 값·마감/다시 열기),
Excel 왕복(`tests/save.rs`: 사본 저장 → 다시 열어 값·글자·수식 재계산·굵게·병합·표시색·이력 시트 확인, 원본에 반영 → 닫고 다시 열어 확인,
충돌 감지·Excel 값 유지, 같은 이름·다른 형식 거절), E2E(마감·다시 열기), 호스트 스모크(다른 이름으로 저장 → 별도 Excel로 열어 확인,
원본에 반영 + 마감 → 참여자 읽기 전용, 기준 갱신으로 바뀐 칸 0, `--running-excel`에서는 사용자 Excel에서 고친 칸 충돌 → Excel 값 유지).
개발 서버 관리 API에 `/__dev/close`(마감·다시 열기)가 더해졌다.

## 6단계: 모니터링 · 히스토리 · 소통 (1d · 1h · 1i)

**4 진행 모니터링(1d)**: 전체 필수 진행률과 마감 카운트다운, 공지 보내기·선택 셀 강조·채팅(안 읽은 수)·스냅샷 버튼.
조회조건(빈 칸인 행이 있으면 맨 끝에 '(빈칸)')·필수 미입력만·최근 삭제된 셀(1시간 안에 지워져 지금도 빈 칸) 필터, **담당자별**(누르면 그 사람이 맡은 행과, 담당자 없는
행(누구나 입력) 중 그 사람이 넣은 값이 지금 남아 있는 행 — 칸마다 마지막으로 바꾼 사람 기준, 남이 덮어쓰거나 지운 칸은 빠진다), **열별 완료**
(누르면 그 열의 필수 미입력 행만). 필터로 병합 칸의 일부 행만 보이면 그 칸은 보이는 행만큼 그리고 영역 안에서 값이 든 칸의 값을 보이되,
읽기 전용(빗금, 고치려 하면 까닭 안내)이다 — 고치려면 필터를 지우거나 설정 화면(1b)에서 고친다. 호스트도 그리드에서 칸 내용을 고칠 수 있고(1b와 같은 편집기, 참여자가 입력 중인 칸은 막음), 열·행 머리글 경계를 끌거나 오른쪽 클릭해 너비·높이를 바꾸고, 오른쪽 클릭으로 행·열 추가·삭제·취소 행 표시도 한다(1b와 같은 메뉴, 참여자에게도 보임). 그리드는 세션의 셀 변경 피드(`HostEvent`, broadcast → Tauri 이벤트 `sheet-changes`)로 바뀐 칸만
고쳐 그리고(바뀐 칸은 바꾼 사람 색으로 잠깐 물든다), 편집 중인 칸은 자물쇠 + 이름표, 커서는 이름표, 필수 미입력은 호박색 + '필수', 강조한 칸은 노랑 + 진한 테두리. **실시간 활동**: 최근 묶음(편집 중인
사람 포함), 삭제가 든 여러 칸·10칸 넘는 묶음·스냅샷 복원은 빨간 묶음으로 띄우고 '되돌리기'·'셀로 이동'.

**소통(1i)**: 공지(대상 전체·미완료자·선택한 사람, 확인하지 않은 공지는 참여자 화면 위 막대로 확인할 때까지 고정 — '중요'는 빨강,
일반은 파랑, 화면을 연 뒤에 온 공지는 테두리가 세 번 차오르고 확성기가 흔들린다, 여럿이면 '모두 확인' — 읽음 집계, 안 읽은
사람에게 다시 보내기), 셀 강조(선택 범위, 보일 사람 담당자·모두 — 담당자면 담당자 없는 칸이 섞인 범위는 모두에게, '남의 행 숨김'이면 그 행이
보이는 사람만, 노란 표시 + 메모가 있으면 말풍선 + '셀로 이동' 알림, 확인 집계, 해제. 참여자는 강조 칸·말풍선을 오른쪽 클릭하거나
알림 탭에서 말풍선을 숨기고 다시 본다 — 그 브라우저에만 기억하고, 숨기면 칸 왼쪽 위 작은 삼각만 남는다. 노란 강조와 확인 집계는
그대로), 채팅(참여자는 전체·호스트에게만, 호스트는 전체·1:1, `#F7`·`#F7:H7` 참조는 `#` 없는 셀블럭 칩으로 보이고 누르면 그
범위 전체를 고른 뒤 테두리를 두 번 깜빡인다, 1,000자·10초에 10통 제한, 글은 글자로만 그려 HTML을 해석하지 않는다). 받는 사람은 보낼 때 명단에서 정하고, 나중에 들어온 사람은 `welcome`으로 받는다.
호스트 화면에는 `CommsSnapshot`을 따로 내보낸다(이벤트 `comms`). 공지·강조 메모·채팅은 적은 그대로 줄을 나눠 보이고, 채팅 입력은
Enter로 보내고 Shift·Ctrl(⌘)·Alt+Enter로 줄을 바꾼다(한글 조합 중 Enter는 조합 확정).

**채팅 '@ 셀 선택'**: 입력 칸에서 글 맨 앞이나 띄어쓰기 뒤에 `@`를 치면 선택 모드가 된다(엑셀 수식의 참조 모드처럼 초점은
입력 칸에 그대로). 그리드를 끌어 놓거나 방향키로 옮기고 Shift+방향키로 넓힌 뒤 Enter, 또는 `@F6:H8 `처럼 주소를 치고 띄우면
`#시트!범위`(시트 이름을 늘 붙임) 참조가 들어간다. 참여자는 시트 탭을 바꿔 다른 시트에서 이어 고를 수 있고, 호스트는 시트를
바꾸면 선택 모드가 끝난다(초안은 남는다). Esc·고르기 전 띄어쓰기·주소가 아닌 글자·입력 칸 밖을 누르면 선택 모드만 끝나고 `@`는
글자로 남는다(`kim@a1`처럼 붙여 쓴 @는 시작하지 않는다). 고르기로 넣은 참조는 Backspace·Delete 한 번에 통째로 지운다. 저장되는
글은 기존 셀 참조와 같아 서버·프로토콜은 그대로다. 받는 쪽에서 앞뒤로 걸친 남의 행은 잘라 내고 보이는 부분만 고르며 알린다.
셀블럭에 머물면(키보드 초점은 바로) 시트·주소·크기와 처음 3행×4열 값을 보이는 미리보기가 뜬다(호스트는 보고 있는 시트만 값).
채팅 탭을 다시 열면 안 읽은 첫 글 위에 '여기부터 새 메시지' 구분선, 위로 올려 읽는 중에 온 글은 따라 내려가지 않고
'새 메시지 n개' 버튼에 센다.

**채팅·공지 알림**: 참여자는 채팅 탭을 보고 있지 않을 때 온 남의 글을 '보낸 사람: 글' 토스트('채팅 열기')로 알리고, 브라우저 탭이
가려졌거나 다른 창을 보는 동안 온 채팅·공지는 탭 제목을 '💬 새 메시지 n개'·'📢 새 공지'로 깜빡여 알린다(돌아오면 멈춘다.
참여자 주소가 http라 OS 알림은 쓸 수 없다). 채팅 초안은 탭을 바꾸거나 사이드바를 닫아도 남는다. 호스트 앱은 창이 뒤에 있을 때
참여자 채팅이 오면 작업 표시줄 단추를 깜빡인다(창이 앞으로 올 때까지, 되살린 기록에는 깜빡이지 않는다). 모니터링 공지·강조 패널은
보낸 목록이 길어져도 입력 칸 높이를 지키고 목록만 패널 안에서 스크롤한다. 호스트 채팅 입력 위에는 받는 사람만 둔다.

**채팅 리액션**(프로토콜 v8): 남의 글에 마우스를 올리면 그 줄 오른쪽 위에(짧은 글에서도 채팅 목록 안에) 👌 OK · ✅ 네 · ❌ 아니요 · 🙏 감사합니다 · 👍 좋아요 · 😢 슬퍼요
막대가 나온다. 한 사람이 한 글에 여러 개를 달 수 있고, 같은 것을 다시 누르면(글 아래 칩을 눌러도) 뗀다. 칩은 이모지·수, 마우스를
올리거나 초점을 주면(터치는 길게 누르면) 단 사람 목록(단 순서, 사람 색 이니셜, '호스트'·'나' 표시)이 뜬다. 호스트(1d 채팅)도 참여자 글에 단다(호스트는 이름이 바뀌어도 같은 사람으로 본다). 내 글에는 달 수 없고, 참여자는 자기에게
보이는 글에만 단다. `chatReact{id, kind}`(토글) → 그 글이 보이는 사람에게 `chatReactions{id, reactions}`, 호스트는 `CommsSnapshot`.
리액션은 `ChatMessage.reactions`로 기록 파일에 함께 남는다(옛 기록 파일은 빈 목록으로 읽는다). 10초에 30번까지.
개발 서버 관리 API `/__dev/chat/react`(`{id, kind}`, 호스트 리액션).

**5 히스토리(1h)**: 셀 변경 기록(`collect_core::history`)을 묶음으로 보여 준다. 칸마다 종류(입력·수정·삭제·되돌림)와 묶음 출처
(붙여넣기·범위 삭제·실행 취소·다시 실행·되돌림·스냅샷 복원·Excel 값 유지 — 참여자가 `setCells`의 `origin`으로 보낸다). 필터: 기간·
사용자·종류·셀/범위·값 검색, '더 보기', CSV 내보내기(Excel용 BOM). 칸 '되돌리기'·'묶음 복원'은 그 뒤에 다시 바뀐 칸이 있으면 묻고
덮어쓴다. 셀 타임라인(원본 → 기록 → 현재)에서 '이 값으로'. **스냅샷**: 불러온 원본, 15분마다 자동(그사이 바뀐 것이 있을 때만),
'지금 저장', 복원 직전(복원도 되돌릴 수 있게). 지금과 다른 칸 수·이후 바꾼 사람, '비교 보기'(앞 500칸), '이 시점으로 복원'.
호스트의 되돌리기·복원도 참여자 입력처럼 버전·이력·진행률에 반영되고 모두에게 간다.

**참여자**: 상단 공지 막대(확인), 도구바(실행 취소 | 서식 | 취소 행 ‥ 그리드·행 단위 | 알림·채팅 바로가기·사이드바 — 호스트 앱처럼
옅은 바탕에 테두리 없는 30px 단추), 오른쪽 사이드바(같은 폭 밑줄 탭 셀 내용·알림·채팅·셀 이력, 안 읽은 수는 빨간 알약, 알림 탭은
확인하지 않은 것 먼저 카드로), 칸 오른쪽 클릭 → 셀 이력(메모가 있는 강조 칸이면 메모 숨기기·셀 이력 메뉴). 셀 이력에서는 **내가 바꾼 마지막 값**만
되돌릴 수 있다(그 밖에는 채팅으로 호스트에게 요청).

**저장소(`crates/collect-store`)**: 시트를 확정할 때마다 `%LOCALAPPDATA%\com.mergemaster.host\sessions\YYYYMMDD-HHMMSS.sqlite`를
만들고 변경 기록(`changes`)·스냅샷(`snapshots`, 셀 값 JSON을 zstd로, 1,000행 × 9열이 수 KB)·메타(통합문서·시트)를 남긴다. 쓰기는 전용
스레드가 하므로 세션 액터가 멈추지 않는다. 앱을 다시 켤 때 이 파일에서 되살리는 일은 7단계에서 한다.

프로토콜 v3(공지·강조·채팅 메시지, `setCells.origin`, `welcome`에 공지·강조·채팅). 바로잡은 것: 호스트 작업(`with`)의 답을 접속자 표·
소통 상태를 내보낸 **뒤에** 돌려준다. 전에는 답이 먼저 와서, 다시 확정한 직후 1c 표가 옛 명단을 계속 보이는 경우가 있었다.

시험: collect-core(종류·묶음·필터·쪽 나누기·되돌리기 계획·스냅샷 차이·CSV), collect-store(압축 왕복, 기록·스냅샷 저장·초기화),
세션(공지 대상·읽음, 강조 대상·숨김 정책·확인·해제, 채팅 경로·1:1·속도 제한, 묶음 출처, 스냅샷·복원·복원 되돌리기, 자동 스냅샷,
저장소, 호스트 피드, 답보다 먼저 내보내기), E2E 4개(`e2e/comms.spec.ts`: 중요 공지·읽음, 강조·셀로 이동·해제, 채팅·#셀 참조,
셀 이력 되돌리기·묶음 출처), 호스트 스모크(모니터링 실시간 반영·담당자 필터·범위 삭제 빨간 묶음 되돌리기·중요 공지 읽음·셀 강조 확인·
채팅 1:1, 히스토리 묶음·셀 타임라인·CSV·스냅샷 비교·복원). 개발 서버 관리 API에 `/__dev/notice`·`highlight`·`highlight/clear`·
`chat`·`comms`·`history`가 더해졌다.

아직 안 되는 것: 앱을 다시 켰을 때 세션 복구·공지·채팅을 파일에 남기기(7단계).

## 7단계: 안정화 · 보안 · 패키징

### 세션 복구

앱이 죽거나(강제 종료·PC 재시작) 호스트가 앱을 닫았다가 다시 켜도 취합을 이어서 한다.

- **무엇을 남기나**: 6단계의 기록 파일(`sessions\YYYYMMDD-HHMMSS-mmm.sqlite`, 업무 id는 메타 `job`)에 변경 기록·스냅샷과 함께 시트·기준 시트·취합 설정·
  소통(공지·강조·채팅·읽음)을 zstd로 압축해 `blobs` 테이블에 둔다. 시트는 통째로 바뀔 때(확정·서식·복원·Excel 값 유지·스냅샷)만 다시 쓰고,
  그 사이의 입력은 변경 기록에 이미 있으므로 되살릴 때 시트 뒤의 기록을 다시 적용한다. 셀 버전·마지막 입력자·이미 반영한 묶음 번호도
  기록에서 다시 만들어, 참여자가 다시 보낸 묶음은 한 번만 반영된다. 서비스 상태(포트·경로·켜짐)와 마감 여부는 메타에 남긴다.
- **이어서 하기**: 앱을 켜면 **끝내지 않은 업무를 모두 저절로 되살린다**(9단계, 예전의 '지난 취합' 배너는 없앴다) — 업무마다 세션을
  되살리고 → 앞 앱이 남긴 숨은 Excel을 한 번에 정리하고(`Session::adopt_orphans_many`) → 업무마다 계산 사본을 다시 열고 →
  공유 중이던 업무는 **같은 포트·같은 경로**로 다시 공유한다(포트를 다른 프로그램이 쓰고 있으면 알리고 취합은 계속). 참여자 브라우저는
  0.5~8초 간격으로 다시 붙어 이름(토큰)으로 다시 입장하고, 끊긴 동안 입력한 값(대기열)을 보낸다.
- **남은 Excel 정리**: 앞 앱이 띄운 계산 사본(임시 폴더 `merge-master\calc-*`)은 닫고 Excel을 끝낸다. 죽은 앱이 쥐고 있던 COM 참조
  때문에 `Quit`만으로는 몇 분 넘게 남아 있어서, 3초 안에 끝나지 않으면 그 프로세스를 끝낸다(앱이 띄운 것으로 확인한 인스턴스만).
  숨은 Excel에 열린 원본은 이 앱이 띄운 것처럼 받아들여 앱을 닫을 때 함께 닫는다(앞 앱이 함께 열어 둔 다른 파일도 저장된 상태면 함께 닫는다. 저장하지 않은 변경이 있는 문서가 있으면 다른 프로그램의 작업일 수 있어 그 Excel은 끝내지 않는다). 사용자가 보는 Excel은 건드리지 않는다.
- 되살리지 않으려면 그 업무를 '업무 끝내기'한다(메타 `ended`, 파일은 남는다). 기록 파일은 최근 20개만 남기고 앱을 켤 때 지운다
  (끝내지 않은 업무의 지금 파일은 오래되어도 남긴다).

### 부하 시험 (`pnpm load`)

`crates/collect-server/tests/load.rs`: 1,000행 × 10열, 30명이 각자 실제 WebSocket으로 접속해 20초 동안 자기 행에 초당 2.5칸씩 입력하고
커서를 초당 5번 움직인다(중간에 한 명이 272칸 붙여넣기). 같은 PC에서 두 번 잰 결과(release 빌드):

| 항목                                       | 1회                                                   | 2회(최종 코드)                                      |
| ------------------------------------------ | ----------------------------------------------------- | --------------------------------------------------- |
| 처리량                                     | 입력 묶음 73/초 · 서버가 보낸 메시지 6,398/초         | 입력 묶음 73/초 · 서버가 보낸 메시지 6,365/초       |
| 반영 지연(보낸 뒤 다른 사람 화면 도착까지) | 51,156건: p50 2.0 · p95 10.1 · p99 11.8 · 최대 78.6ms | 51,185건: p50 1.6 · p95 3.8 · p99 6.3 · 최대 99.6ms |

목표(LAN 반영 지연 < 100ms)를 p95·p99로는 넉넉히 넘는다. 최대값은 실행마다 크게 달라(78.6 / 99.6ms) 드물게 튀는 경우가 있다
(같은 PC에서 클라이언트 30개와 서버가 CPU를 나눠 쓰는 영향이 섞여 있다). 실제 LAN에서는 여기에 망 왕복 시간(사내 유선 보통 1ms 안팎)이
더해진다.

### 보안

참여자 서버는 사내 LAN의 HTTP 서버다. 막아 둔 것:

- **WebSocket**: Origin 검사(Origin이 없거나, 접속한 주소와 같거나, loopback일 때만 — 참여자가 연 다른 사이트의 페이지가 그 브라우저를
  통해 붙는 것을 403으로 막는다), 메시지 4MB, 연결마다 초당 50통(순간 200통)까지 — 넘는 메시지는 버리고 경고하며, 500통을 버리면 끊는다.
- **입력 길이**: 이름 20자, 셀 글자 2,000자, 한 묶음 20,000칸, 공지 2,000자, 강조 메모 500자, 채팅 1,000자(10초에 10통), 채팅 리액션 10초에 30번, 토큰 64자,
  묶음 번호 80자.
- **HTTP 응답 헤더**: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, CSP(`default-src 'self'`,
  `frame-ancestors 'none'`, `form-action 'none'` 등). 정적 파일은 내장 자산만(경로 탈출 없음).
- **서버가 강제하는 것**: 시트는 입장한 연결에만 보낸다(`/api/sheet`는 404). '남의 행 숨김'이면 남의 행 값을 아예 빼고 보낸다.
  권한·입력 형식·마감(마감 시각·호스트 마감) 검사는 서버에서 한다. 마지막 업무의 공유를 멈추면 포트를 닫는다(시험으로 확인).

**알고 쓰기(구조상 한계)**

- **IP로 사람을 알아본다.** IP 명단에 있는 IP에서 오면 그 이름으로 들어온다(같은 망에서 IP를 바꿔 달면 흉내 낼 수 있다 —
  고정 IP·DHCP 예약을 쓰는 사내망에서 쓴다). 명단 밖 IP는 이름을 대도 호스트가 승인해야 들어온다. 호스트 접속자 표·승인 대기에
  IP가 보이고, 모든 입력은 이름·시각과 함께 기록되어 되돌릴 수 있다.
- **에이전트 PC의 자동 승인은 이름만 본다.** 같은 사내망의 누구나 남의 이름을 대고 들어올 수 있다(지금 접속 중인 이름만 막는다). 모든 입력이
  이름·IP와 함께 기록되므로 호스트가 모니터링·히스토리에서 보고 끊거나 되돌린다(끊은 이름은 다시 승인해야 들어온다).
- **관리 키가 관리자 자격이다.** 에이전트로 넘긴 업무는 넘긴 호스트 앱이 관리 키(`agents.json`)로 관리자 연결을 연다. 평문 HTTP라 같은 망에서
  엿보면 그 키로 관리자가 될 수 있다(위 '암호화하지 않는다'와 같은 한계).
- **암호화하지 않는다(HTTP).** 같은 망에서 오가는 값을 엿볼 수 있다. 급여·개인정보처럼 민감한 자료에는 쓰지 말고 신뢰할 수 있는
  사내망에서만 쓴다. 접속 경로(`/q4` 같은 slug)는 비밀번호가 아니다.
- 권하는 운영: 필요할 때만 서비스를 켜고 끝나면 중지, 남의 값을 보일 필요가 없으면 '남의 행 숨김', 명단 밖 IP는 승인하기 전에 확인.

### 패키징 · 버전 · 서명

- `pnpm app:build` → 참여자 웹 빌드 → `tauri build`(호스트 화면 빌드, release 실행 파일, NSIS 설치 파일) →
  `release/merge-master_<버전>_x64-setup.exe`와 `SHA256SUMS.txt`.
- **설치 파일**: NSIS, 현재 사용자 설치(관리자 권한 없이 `%LOCALAPPDATA%` 아래에 설치), 한국어 설치 화면, 시작 메뉴 '엑셀 취합 도구'.
  사내망(인터넷 없음)에서도 설치되도록 **WebView2 오프라인 설치 파일**을 넣는다(설치할 PC에 WebView2가 없을 때만 조용히 설치).
  그래서 설치 파일이 약 211MB다(WebView2 설치 파일이 약 204MB, 앱은 압축해서 약 7MB — 실행 파일 19MB). 빌드하는 PC는 처음 한 번 NSIS 도구와 WebView2 설치
  파일을 내려받는다(이후 캐시). `MM_WEBVIEW=bootstrapper`로 빌드하면 작은 부트스트래퍼를 넣은 `…-bootstrap-setup.exe`가 된다(WebView2 부분이 1.7MB로 줄어 10MB 안팎,
  WebView2가 없는 PC는 설치할 때 인터넷 필요 — Windows 11과 업데이트된 Windows 10에는 이미 있다).
- **방화벽**: 설치할 때 규칙을 넣지 않는다. 처음 서비스를 열 때 Windows가 묻는 허용 대화상자에서 허용한다.
- **버전**: `Cargo.toml`의 `[workspace.package] version` 하나가 기준이다(`pnpm bump 1.0.1`, `pnpm bump patch`). Tauri가 이 값을 설치 파일
  이름·제품 버전에 쓰고, 호스트 사이드바 아래에 `v1.0.0`으로 보인다. 지금 버전은 1.0.0.
- **코드 서명**(선택, 환경 변수): `MM_SIGN_THUMBPRINT`(Windows 인증서 저장소의 코드 서명 인증서 지문 → signtool, sha256,
  타임스탬프 `MM_SIGN_TIMESTAMP` 기본 `http://timestamp.digicert.com`) 또는 `MM_SIGN_COMMAND`(다른 서명 도구, 파일 자리 `%1`).
  Tauri가 실행 파일·설치 파일을 모두 서명하고 스크립트가 설치 파일의 서명을 `Get-AuthenticodeSignature`로 확인한다(인증서가 없어 이
  경로는 실제로 돌려 보지 못했다). 서명하지 않으면 설치할 때 SmartScreen이
  '알 수 없는 게시자'로 경고한다.
- **에이전트 주소 기본값**(선택, 환경 변수): `MM_AGENT_URL`(예: `http://10.0.0.7:8090`, `PC01`)로 빌드하면 1c '에이전트 PC'의 주소
  입력란에 그 주소가 채워진다(한 번도 연결하지 않은 PC만 — 연결한 적이 있으면 마지막 주소). Release 워크플로는 저장소 변수
  `AGENT_URL`(Settings → Secrets and variables → Actions → Variables)을 넣는다. 실행 파일에 들어가므로 바꾸면 다음 Release부터 반영된다.
- `pnpm smoke:release`는 release 실행 파일(내장 화면 `tauri.localhost` · 서버에 내장된 참여자 웹)로 호스트 스모크 전체를 돌린다.
- **에이전트 배포**(`.github/workflows/agent.yml`, Actions → Agent → Run workflow): Release 워크플로와 따로 돌린다. 마지막 Release를
  찾아 빌드 기준(그 Release의 태그 — 기본, 호스트 앱과 같은 코드 / 기본 브랜치 — 에이전트만 고쳐 다시 배포)으로 참여자 웹 → 에이전트 시험 →
  release 빌드를 하고, 그 Release에 있던 `merge-master-agent-*.exe` 첨부를 지운 뒤 `merge-master-agent-<버전>.exe`를 올린다(같은 Release에
  여러 번 돌리면 갈아 끼운다). 에이전트가 들어가기 전에 만든 Release의 태그로는 빌드할 수 없다(기본 브랜치로 돌리거나 새 Release를 만든다).

## 8단계: 여러 시트 함께 취합

같은 통합문서에서 시트를 여러 개 골라 한 세션으로 취합한다. 시트는 **세션 안 순번**(불러온 순서 = 통합문서 시트 순서, 프로토콜·
기록의 `sheet`)으로 가리키고, Excel을 다룰 때만 시트 이름을 쓴다. 시트가 하나면 화면·주소·파일 모양은 전과 같다.

- **1a**: 체크하거나 시트 이름을 누른 시트를 미리 본다. 확정하면 아직 읽지 않았거나 설정이 바뀐 시트를 차례로 읽고
  한 번에 확정한다(`import_commit(sheets)`, 상태 줄에 '‘인력계획’ 시트 읽는 중 (2/3)').
- **시트마다 / 공통**: 열 역할·필수·형식·조회조건·안내, 셀 예외, 행 배정 기준 열·범위 배정, 참여자 권한(서식·남의 행·크기 조절·
  수식 칸·행 추가)은 시트마다 정한다. 제목·안내·요청자·마감·마감 동작은 공통이라 어느 시트에서 고쳐도 모든 시트 설정에 같은 값이
  들어간다(`ConfigEdit::reach`). 명단은 **모든 시트 명단의 합집합**이다 — 합집합을 씨앗으로 시트마다 권한 엔진을 만들어
  (`Access::compile_with`) 사람 번호·색이 시트마다 같다. 담당자 없는 칸은 어느 시트든 명단의 누구나 입력한다. 공지·채팅은 공통,
  강조는 그 시트의 칸, 편집 잠금은 시트를 넘어 한 사람 한 칸.
- **호스트 화면**: 1b·1d 그리드 아래 시트 탭(엑셀처럼, 1d는 남은 필수 칸 수). 1b·1c·1d·1h는 보던 시트를 함께 쓴다. 1c 현재 위치·
  배정 요약은 `인력계획!F7`처럼 시트 이름을 붙이고, '배정 후 승인'은 시트를 고르거나 범위에 `시트!`를 적는다. 1d 진행률·담당자별은
  모든 시트 합, 열별 완료는 보는 시트. 활동·강조·채팅의 `#인력계획!F7`을 누르면 그 시트로 가서 그 칸을 보인다. 1h는 시트 필터와
  `인력계획!E5` 범위, 타임라인·스냅샷 비교도 시트를 안다.
- **참여자**: 그리드 아래·상태 바 위에 시트 탭(내 남은 필수 칸 수, 확인하지 않은 강조 점). 시트마다 선택·필터·되돌리기를 따로 두고,
  새로 고쳐도 보던 시트를 이어서 본다(주소 경로별). 강조·알림·채팅의 셀 참조는 그 시트로 데려간다. 끊긴 동안의 입력(대기열)은
  시트 이름과 함께 남아 다시 붙으면 그 시트에 보낸다.
- **저장**: 저장·복사는 한 번, 시트마다 바뀐 칸만 쓰고 다시 읽어 확인한다. '변경 이력' 시트는 하나이고 시트가 여럿이면 '시트' 열이 붙는다
  (CSV 내보내기도 같다). 그사이 Excel에서 고친 칸·표 밀림은 시트마다 보여 주고, 어느 시트든 표가 밀린 것 같으면 '그래도 저장'을 확인해야
  한다. 원본에 반영하면 시트마다 기준 시트가 바뀐다. 요약은 합계 + 시트별, 비어 있는 칸은 `인력계획!E5`.
- **수식 재계산**: 계산 사본은 통합문서 전체라 시트를 넘는 수식도 Excel이 계산한다.
- **프로토콜 v5**: 좌표가 든 메시지마다 `sheet`(없으면 0). `welcome`은 공통 부분 + `sheets: SheetView[]`(시트마다 그 사람 기준 모델·
  상태 비트·버전·열 규칙·권한·행 담당자·진행률).
- **하위 호환**: v1.2.0의 기록 파일(시트 하나)도 '이어서 하기'가 된다 — 블롭은 하나·여러 개 모두 읽고, 스냅샷 값도 옛 모양을 읽고,
  `changes` 표에는 `sheet` 열을 더한다(기본 0).

시험: collect-core(합집합 명단·씨앗 권한, 시트별 이력·CSV·이력 표의 시트 열, 요약 합치기, `시트!` 주소), collect-store(옛 스키마
파일 이어 쓰기), 세션(`session/sheets_tests.rs`: 시트마다 `welcome`·편집·권한, 시트를 넘는 잠금, 없는 시트 거절, 공통 설정, 공지·강조·
승인 범위, 스냅샷·복원, 수식 없는 시트의 재계산, 기록 파일에서 되살리기, 옛 단일 시트 파일 되살리기, 시트 수가 바뀌는 다시 확정),
TS(`a1` 시트 접두, 참여자 대기열·시트별 되돌리기), E2E 5개(`e2e/sheets.spec.ts`, 시트 두 개 서버), 호스트 스모크(1a 시트 더 고르기·
크게 보기 탭). excel-com·src-tauri는 Windows에서 `pnpm smoke:host`로 확인한다.

## 9단계: 여러 업무 동시 진행

한 사람이 기간이 겹치는 여러 취합 업무를 맡으므로, **취합 업무 하나 = 세션 하나**로 보고 호스트 앱에서 여러 업무를 함께 진행한다.
참여자는 같은 호스트 PC 주소로 들어와 업무 목록(업무명)에서 골라 들어간다.

| 주소                            | 내용                                                                                                    |
| ------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `http://<호스트IP>:<포트>/`     | 공개 중인 업무 목록(업무명·요청자·마감·접속 수, 내 IP가 IP 명단에 있고 그 업무 명단에 있으면 '내 담당') |
| `http://<호스트IP>:<포트>/q4`   | 그 업무(주소 경로마다 이름·토큰·보던 시트·대기열을 따로 기억, 탭 제목은 업무명)                         |
| `GET /api/sessions`             | 업무 목록 JSON                                                                                          |
| `/api/session?s=q4`, `/ws?s=q4` | 그 업무의 공개 정보·WebSocket(`s`를 빼면 공개 중인 업무가 하나일 때만 그 업무, 둘 이상이면 400)         |

- **호스트 화면**: 사이드바 위쪽 '취합 업무' 목록 — 업무명·파일·공유 중 접속 수·승인 대기·필수 진행률·마감, 다른 업무의 안 읽은 채팅 점.
  업무를 고르면 그 업무의 단계 화면이 보이고(단계는 업무마다 기억), '+ 새 취합'은 빈 업무를 만들어 1a로 간다. 업무마다 1a 미리보기·
  1b 설정·접속자·소통·히스토리·저장이 따로다. 업무에 딸린 command는 모두 `job`(업무 id)을 받고, 화면 이벤트도 업무별 이름
  (`participants:{id}`, `sheet-changes:{id}`, `comms:{id}`, `recalc-status:{id}`, `config-changed:{id}`)이며 목록은 `jobs` 이벤트로 받는다.
- **공유**: 참여자 서버는 하나(포트 하나)이고 업무마다 주소 경로로 공유한다(`collect_server::Hub`). 포트는 모든 업무 공통이라 다른 업무가
  공유 중이면 바꿀 수 없고, 주소 경로는 업무마다 달라야 한다(새 업무는 `q4`, `q4-2`…). 한 업무의 공유를 멈추면 그 업무의 연결만
  `closing`을 받고 닫히며(다른 업무는 그대로), 마지막 업무를 멈추면 포트를 닫는다. 같은 업무명으로 공유 중인 업무가 있으면 1c가 알린다.
- **IP 명단은 모든 업무 공통**: 명단의 PC는 어느 업무든 이름을 묻지 않고 그 이름으로 바로 들어온다(그 업무 명단에 없으면 명단에 더해진다).
  명단 밖 PC는 업무마다 이름을 넣고 그 업무 호스트 승인을 기다린다.
- **업무 끝내기**(사이드바 ×, 6 저장): 공유를 멈추고 접속 중인 참여자에게 '호스트가 이 업무를 끝냈습니다'(다시 붙지 않음), 계산 사본을
  닫고, 기록 파일에 `ended`를 남겨 앱을 다시 켜도 되살리지 않는다(파일은 남는다). 저장하지 않은 변경이 있으면 확인 대화상자가 알린다.
  업무를 모두 끝내면 목록이 빈다(빈 업무를 저절로 만들지 않는다). 그때는 '+ 새 취합' 또는 화면의 '새 취합 시작'으로 새로 시작한다.
  같은 주소 경로를 새 업무가 다시 쓰면 참여자는 업무 id(`SessionInfo.job`)가 바뀐 것을 보고 앞 업무의 대기열·토큰을 버린다.
- **복구**: 앱을 켜면 업무마다 가장 최근 기록 파일(메타 `job`)을 되살리고(끝냄·버림 제외), 공유 중이던 업무는 다시 공유한다
  (포트는 가장 최근 업무의 것). 여러 업무 전(v1.2.0) 기록 파일은 디렉터리에서 가장 최근 파일일 때만 한 번 되살린다.
  고르기·정리 규칙은 `collect_server::session::files`(순수 함수, 단위 시험).
- **Excel**: 수식이 있는 업무마다 계산 사본(숨은 Excel) 하나(`Session::open_calc_for(업무 id, …)`). Excel 작업은 한 스레드라 긴 불러오기·
  저장 동안 다른 업무의 재계산은 잠깐 기다린다. 같은 통합문서·시트를 두 업무가 취합하면 1a가 알리고, 둘 다 원본에 반영하면 저장 전
  '그사이 Excel에서 고친 칸' 확인으로만 막는다(한쪽은 다른 이름으로 저장하길 권한다).

시험: collect-server(`hub.rs` 주소 경로 검사·공개/공개 중지·목록 순서·내 담당, `tests.rs` 포트 하나에 업무 둘 — 주소별 입장·승인·토큰,
IP 명단 공통, 한 업무만 공개 중지(`closing{ended}`), 다시 공개·토큰 재입장, `s` 생략 규칙, `session/files.rs` 되살릴 파일·정리 규칙,

## 10단계: 에이전트 PC에서 서비스

관리자 PC를 꺼도 취합이 계속되도록, 서비스(참여자 서버)를 **에이전트가 설치된 다른 PC**에서 돌린다. 1c에서 '에이전트 PC'를 고르고
넘기면 에이전트가 마감 일시까지 서비스하고, **마감 시각이 되면 정해 둔 곳에 엑셀로 저장하고 그 서비스를 끝낸다**. 무기한 서비스를
막기 위해 에이전트 PC에서는 마감이 필수다.

에이전트 PC의 부하를 줄이려고 **서비스 중에는 Excel을 열지 않는다**: 관리자 PC가 처음 불러온 데이터(넘길 묶음)만으로 서비스하고,
Excel은 마감 저장 때만 별도 저장 프로세스에서 잠깐 띄운다. 관리자 앱이 접속해 있으면 관리자 PC에서 언제든 지금 상태를 새 파일로
저장할 수 있고, 마감 저장에 실패하거나 에이전트 PC에 Excel이 없으면 취합 데이터를 남겨 두었다가 관리자 앱이 접속할 때 그 PC에서
저장한다(**관리자 저장 대기**).

**에이전트 설치**(`merge-master-agent-<버전>.exe`, Release 페이지 — 위 '에이전트 배포')

- 창 없이 **작업 표시줄 트레이**에서 돈다. 설치 없이 실행하고, 한 PC에 하나만 뜬다. 데이터 폴더는 `%LOCALAPPDATA%\merge-master-agent`
  (`agent.json` 설정, `ip-names.json` 에이전트 PC의 IP 명단, `services\<id>\` 서비스마다 기록 파일·원본·상태·취합 데이터
  `result.mmsave`(마감 때 남기고 엑셀로 저장하면 지운다), `logs\agent.log`, `webview\` IP 명단 창).
- **Excel은 있으면 그 PC에서 저장한다(없어도 된다)**: 서비스 중에는 Excel을 띄우지 않는다 — 수식 칸은 넘길 때의 값을 보여 주고(화면에는
  '저장할 때 계산'), 저장할 때 Excel이 계산한다. 마감 때는 원본 사본에 값을 쓴다(호스트의 '다른 이름으로 저장'과 같은 결과 — 서식·병합·변경
  이력 시트). Excel이 없으면 서비스는 그대로 받고, 마감 때 취합 데이터만 남겨 관리자 PC에서 저장한다. Excel 첫 실행·정품 인증 창이 자동
  저장을 멈추게 하므로 그 PC에서 Excel을 한 번 켜 끝내 둔다. 숨은 Excel만 쓰고 그 PC 사용자가 띄운 Excel에는 열지 않는다.
- **로그인한 상태로 둔다**: Excel 자동화에는 로그인 세션이 있어야 한다. 트레이 메뉴 'Windows 시작 시 실행'(지금 사용자의 시작 프로그램)을
  켜 둔다(작업 스케줄러의 '로그온 여부와 관계없이 실행'은 쓰지 않는다). 서비스가 있는 동안은 절전에 들어가지 않게 한다.
- **방화벽**: 켤 때 포트(기본 **8090**, 참여자 접속과 관리 API를 같이 받는다)를 열므로 처음 한 번 Windows가 묻는 허용 창에서 허용한다.
  허용은 실행 파일 경로 기준이라 **같은 폴더에 같은 이름으로** 바꿔 넣는 것이 좋다(이름이 바뀌면 다시 묻는다).
- **트레이 메뉴**(오른쪽 클릭): 버전 · 주소 복사 · (Excel이 없으면 'Excel 없음 — 마감 저장은 관리자 PC에서') · 진행 중 n개/관리자 저장
  대기 n개/저장 실패 n개 · 서비스(마감·상태, 주소 복사·지금 저장하고 끝내기·저장 없이 끝내기·다시 저장·저장한 파일 보기, 관리자 저장
  대기면 이 PC에서 다시 저장(Excel이 있을 때)·취합 데이터 폴더 열기·저장 없이 끝내기(취합 데이터를 지운다고 묻는다)) ·
  **IP 명단 관리… (n명)** · **기본 저장 폴더**(표시·바꾸기·열기) · Windows 시작 시 실행 · 로그 폴더 · 설정 파일 · 끝내기(진행 중이면 묻는다 — 다시 켜면 이어서 하고, 그사이 마감이 지났으면 켜자마자 저장한다. 열린 관리자 연결이 막지 않는다).
- **IP 명단 관리 창**(프로그램 창, WebView2): 에이전트 PC의 IP 명단(`ip-names.json`) — IP·이름 추가/고치기/빼기·검색·접속 중 표시·같은 이름이
  여러 IP면 알림, JSON 불러오기(지금 명단을 바꿀지 묻는다)·내보내기, **승인 대기**(까닭·승인/거부, 같은 이름이 접속 중이면 앞 기기가 끊긴다고
  묻는다), **명단 밖 접속자**('명단에 넣기'), **넘겨받은 명단**(서비스마다 — '이 PC 명단에 넣기'·'이 업무에서 빼기', 에이전트 명단과 같은 IP는
  '이 PC 명단이 먼저'). 창은 하나만 뜨고(이미 열려 있으면 앞으로) 닫으면 없앤다. HTTP 경로가 없어 이 PC에서만 다룬다(`window.ipc`). 참여자 이름은
  글자로만 넣는다(HTML로 해석하지 않음). WebView2 데이터는 데이터 폴더의 `webview\`. WebView2 런타임이 없으면 설치 주소와 함께
  '`ip-names.json`을 고친 뒤 다시 켜기'를 안내한다.
- **IP 명단은 에이전트 PC 것이 이긴다**: 서비스마다 실제 명단 = 에이전트 명단 + 그 서비스가 넘겨받은(호스트) 명단 중 에이전트 명단에 없는 IP.
  넘겨받은 명단은 에이전트 파일에 섞지 않는다(그 서비스에서만 쓴다). 명단을 바꾸면 서비스 중인 세션에 바로 걸린다(기다리던 사람은 바로 들어온다).
- **참여자는 자동 승인**(3단계 '자동 승인'): 명단 밖 사람도 입력한 이름 그대로 바로 들어온다(관리자가 미접속일 수 있으므로).
- 설정(`agent.json`): `baseDir`(기본 저장 폴더, 기본 문서\엑셀 취합 결과), `port`(8090), `maxDays`(마감은 받는 때부터 60일 안).

**넘기기**(호스트 1c '에이전트 PC')

1. 에이전트 주소(PC 이름 또는 IP, 포트를 빼면 8090 — 입력란에는 마지막으로 연결한 주소, 없으면 빌드 때 넣은 기본 주소 `AGENT_URL`이
   채워진다) → '연결 확인': PC 이름·버전·Excel(없으면 '마감 때 이 PC에서 저장'이라고 알린다 — 넘길 수는 있다)·기본 저장 폴더·그 PC
   시각. 마감은 **에이전트 PC 시각**으로 재고(옆에 그 시각, 이 PC 시계와 2분 넘게 다르면 알린다), 지금부터 5분 뒤 ~ 최대 기간 안이어야 한다.
2. **마감 때 저장할 곳**: '폴더 고르기…'가 에이전트의 기본 저장 폴더 아래를 보여 준다(이 PC의 파일 창은 다른 PC를 볼 수 없어 에이전트에 묻는다).
   하위 폴더로 들어가고, 없는 폴더(새 폴더)도 고를 수 있다 — 저장할 때 중간 폴더까지 만든다. 파일 이름 기본값은 `원본명_취합_마감일.확장자`
   (원본과 같은 형식), 같은 이름의 파일이 있으면 `_2`, `_3`을 붙인다(덮어쓰지 않는다). 기본 저장 폴더 밖(`..`·드라이브·정션)으로는 나가지 못한다.
3. 주소 경로(바라는 값 — 다른 업무가 쓰고 있으면 에이전트가 `-2`, `-3`…을 붙인다), 함께 넣기(저장 화면과 같은 기본값).
4. '에이전트에서 공유 시작' → 넘기기 전 확인(불러온 뒤 Excel에서도 고친 칸 수 — 마감 저장 때 취합 값으로 쓴다, 표 위치가 바뀌었으면
   '그래도 넘기기') → 마감과 '마감 시각이 되면 읽기 전용'을 설정에 쓰고, **원본의 지금 상태**(`SaveCopyAs` — 저장하지 않은 Excel 변경도 든다)와
   **기록 파일 사본**(`VACUUM INTO` — 시트·설정·기준 시트·소통·재접속 토큰·변경 기록)을 한 묶음으로 보낸다. 원본 사본은 이 PC에도
   남긴다(앱 데이터 폴더 `agent-sources\` — 이 PC에서 저장할 때 쓴다, 서비스가 끝나거나 목록에서 지우면 지운다).
5. 에이전트가 받으면 **이 PC의 업무는 끝나고**(기록 파일에 `ended`·`handedOff`, 다시 켜도 되살리지 않는다) 사이드바 **'에이전트에서 진행 중'**에
   보인다. 응답을 놓쳤으면 에이전트에 물어 받았으면 끝내고, 받지 않았으면 이 PC의 업무를 그대로 둔다.

공유 시작 전에만 넘긴다(이 PC에서 공유 중이면 '에이전트 PC'를 고를 수 없다 — 공유를 멈춘 뒤 넘긴다).

**에이전트에서 진행 중**(사이드바, 3초마다 상태): 상태(서비스 중·저장 중·저장하고 끝냄·관리자 저장 대기·저장 실패·저장 없이 끝냄·
연결 안 됨)·접속·승인 대기·필수 진행률·마감·안 읽은 채팅 점. 넘긴 서비스는 앱 설정 폴더의 `agents.json`(에이전트 주소·서비스 id·관리 키)에 기억한다.

**호스트 앱에서는 여전히 관리자(최고권한)**: 서비스 중인 에이전트 업무를 고르면 **이 PC 업무와 같은 업무 화면**이 열린다(관리자 연결 — 아래).
설정(열 역할·셀 예외·담당자 배정·참여자 권한·서식·표 구조), 모니터링(그리드 보기·고치기·크기, 진행률, 활동 피드), 공지·셀 강조·채팅·리액션,
히스토리(되돌리기·묶음 복원·'이 값으로'·CSV 내보내기 — 파일은 이 PC에), 스냅샷(찍기·비교·복원), 참여자(범위 붙여 승인·거부·연결 끊기·편집 잠금
해제), 취합 마감·다시 열기, 마감 일시 바꾸기를 이 PC 업무처럼 한다. 달라지는 것:

- 1 불러오기는 비활성(다시 불러올 수 없다). 3 서비스는 서비스 위치가 그 에이전트 PC로 정해져 있고(네트워크·넘기기 없음), 공유 주소는
  에이전트 주소, **마감은 필수**(에이전트 PC 시각 — 비우거나 범위 밖이면 에이전트가 거절, 바꾸면 에이전트가 그 시각에 저장한다), 마감 동작은
  늘 '읽기 전용'(마감 순간 입력을 막고 에이전트가 저장한다). 이 PC의 IP 명단도 그 서비스에 보낸다(에이전트 PC 명단에 같은 IP가 있으면 그쪽이 먼저).
- 마지막 단계는 **에이전트**: 상태·남은 시간(에이전트 시각)·수식 계산('저장할 때 계산')·저장할 곳·저장한 파일·주소/안내 문구 복사,
  **지금 저장하고 끝내기** / **저장 없이 끝내기**, 저장 실패면 **다시 저장**. 저장을 시작하면 관리자 연결의 고치기는 거절된다(보기는 된다).
- **이 PC에 지금 상태 저장…**(서비스 중, 에이전트에 닿을 때): 에이전트에서 지금 상태(취합 데이터)를 받아 넘길 때 남긴 원본 사본에 써서 이
  PC에 새 파일로 저장한다(이 PC의 숨은 Excel — 마감 저장과 같은 결과, 함께 넣기는 넘길 때 고른 것, 기본 경로는 원본 폴더의
  `원본명_취합_오늘`). 서비스는 그대로 이어지고, 원본 통합문서와 열린 Excel은 건드리지 않는다.
- **관리자 저장 대기**: 에이전트에 다시 닿으면 취합 데이터를 저절로 이 PC에 받아 두고(앱 데이터 폴더 `agent-results\`) 알림·작업 표시줄
  깜빡임으로 알린다. '에이전트' 단계의 **이 PC에 저장…**(기본 경로는 원본 폴더 + 에이전트가 저장하려던 이름)으로 저장하면 에이전트에
  알려 그쪽 취합 데이터를 지우고 '저장하고 끝냄(이 PC)'이 된다. 알리지 못했으면(에이전트가 꺼짐) 기억해 두었다가 다시 닿을 때 알린다.
  에이전트 PC에 Excel이 있으면 **에이전트 PC에서 다시 저장**도 된다. **저장 없이 끝내기**는 남은 취합 데이터를 지운다.
- 에이전트에 닿지 않으면 '다시 연결하는 중 — 보이는 내용은 마지막으로 받은 것'이고, 다시 붙으면 화면이 다시 읽는다. 넘기는 중·연결할 수
  없음·끝남·에이전트가 거절함(관리 키·버전)이면 진행·저장만 보이는 화면이고, 끝났으면 목록에서 지운다.
- 참여자 채팅이 오면 이 PC 업무처럼 작업 표시줄 단추가 깜빡인다.

**마감 때**(에이전트, 1초마다 점검): 마감 순간 세션이 바로 읽기 전용(입력·잠금 거절) → **취합 데이터부터 남긴다**(`result.mmsave` —
시트마다 기준·지금 시트·변경 기록·함께 넣기, zstd. 디스크까지 쓴 뒤 바꿔 넣는다) → 에이전트 PC에 Excel이 있으면 **별도 저장
프로세스**(`merge-master-agent.exe --save-worker`, 창 없음)가 숨은 Excel로 원본 사본에 쓰고 저장(호스트의 '다른 이름으로 저장'과 같은
저장 계획, 충돌 칸은 취합 값) → 취합 데이터를 지우고 공유를 닫는다(참여자는 '마감 시각이 지나 공유가 닫혔습니다', 호스트가 끝내면 '호스트가
이 업무를 끝냈습니다'). 저장에 실패하면 1분 뒤 다시(모두 3번), 그래도 안 되거나 Excel이 없으면 **관리자 저장 대기**로 두고 공유를 닫고 세션을
내린다(취합 데이터 파일에 모두 들어 있다). 취합 데이터조차 남기지 못했으면(디스크 가득 등) **저장 실패**로 두고 세션을 남겨 '다시 저장'할 수
있다.

- **강제 종료 막기**: Excel·COM은 에이전트 프로세스 밖(저장 프로세스)에서만 돈다. 저장 프로세스가 죽거나 Excel이 멈춰도 에이전트(다른
  서비스·참여자 서버)는 그대로이고 그 시도만 실패로 센다. 저장 하나는 10분까지 기다리고, 넘으면 저장 프로세스와 그 Excel(프로세스 번호를
  받아 두고 지금도 `EXCEL.EXE`일 때만)을 끝내고 반쯤 쓴 파일을 지운다. 저장은 한 번에 하나씩(마감이 겹쳐도 Excel은 하나).
- 에이전트가 꺼져 있던 사이 마감이 지났으면 켜자마자 저장한다. 엑셀로 저장하던 도중 꺼졌으면(기록에 '저장 시작'이 남아 있으면) 시도 한
  번으로 센다. 트레이 '끝내기'로 멈춘 저장은 세지 않고 다시 켜면 바로 다시 한다. 관리자 저장 대기는 다시 켜도 그대로다(세션은 되살리지
  않는다).
- 끝난 서비스 폴더는 14일 뒤 지운다(저장한 엑셀은 그대로). 관리자 저장 대기는 지우지 않는다.

**관리 API**(`/agent/*`, 참여자 서버와 같은 포트, JSON, 오류는 `{message}`)

| 요청                                         | 내용                                                                                |
| -------------------------------------------- | ----------------------------------------------------------------------------------- |
| `GET /agent/info`                            | PC 이름·버전·관리 API 판·기본 저장 폴더·포트·주소·지금 시각·Excel·서비스 수         |
| `GET /agent/folders?path=a/b`                | 기본 저장 폴더 아래 폴더 하나(하위 폴더·엑셀 파일, 없는 폴더면 `exists: false`)     |
| `POST /agent/services`                       | 넘길 묶음(`MMAGENT` + 넘길 내용 JSON + 기록 파일 + 원본) → 주소 경로·주소·저장 경로 |
| `POST /agent/status`                         | `[{id, token}]` → 서비스마다 상태(없거나 관리 키가 틀리면 그 까닭)                  |
| `POST /agent/services/{id}/approve`·`reject` | 승인 대기 승인·거부(관리 API 1 호스트 앱용)                                         |
| `GET /agent/services/{id}/host`              | 관리자 연결(WebSocket, 관리 API 2 이상 — 아래)                                      |
| `POST /agent/services/{id}/finish`           | `{save}` 지금 저장하고 끝내기 / 저장 없이 끝내기                                    |
| `POST /agent/services/{id}/retry`            | 저장 실패·관리자 저장 대기를 에이전트 PC에서 다시 저장                              |
| `GET /agent/services/{id}/save-data`         | 취합 데이터(`MMSAVE`): 마감 때 남긴 것, 서비스 중이면 지금 상태                     |
| `GET /agent/services/{id}/source`            | 넘겨받은 원본 통합문서(이 PC에 원본 사본이 없을 때)                                 |
| `POST /agent/services/{id}/host-saved`       | `{savedPath, savedAtMs}` 관리자 PC에서 저장함 → 취합 데이터를 지우고 끝냄           |

- 모든 요청에 헤더 `x-mm-agent`(관리 API 판, 지금 **3**)가 있어야 한다. 에이전트는 1~3을 받는다(옛 호스트 앱의 HTTP 요청 — 판 3보다
  옛 앱에는 관리자 저장 대기를 '저장 실패'로 보낸다). 새 호스트 앱이 옛 에이전트에 보내면 426과 함께 '같은 버전의 에이전트로 바꿔
  주세요' — 옛 에이전트는 지운 행·숨김 해제를 몰라 엉뚱한 행에 저장한다.
  브라우저 요청(`Origin` 헤더)은 받지 않는다 — 참여자가 연 다른 사이트의 페이지가 그 브라우저를 통해 에이전트를 다루지 못하게(관리자 연결도).
- **접근 제한 없음**(참여자 서버와 같은 수준 — 같은 사내망이면 누구나 넘길 수 있다). 서비스마다 넘긴 호스트가 만든 **관리 키**가 있어야
  그 서비스를 다룰 수 있다(헤더 `x-mm-token`, 끝까지 비교) — 관리자 연결의 자격이기도 하다(7단계 보안). 트레이 메뉴는 키 없이 다룬다.
- **관리자 연결**(`agent_protocol::link`): 호스트가 `{id, call}`(`host` — 호스트 앱의 업무 command와 같은 `collect_server::host::HostRequest`,
  `state` — 시트·접속자 표·소통·수식 계산·상태, `ipNames` — 호스트 IP 명단)을 보내면 같은 `id`로 `ok{value}`/`err{message}`. 그 밖에 세션이 바뀌면
  `push`(셀 변경은 바로, 접속자 표·소통·수식 계산·서비스 상태는 250ms마다 바뀐 것만). 호스트 앱은 받은 것을 이 PC 업무와 같은 이름의 이벤트로
  화면에 보낸다(업무 id 자리에 서비스 id). 서비스 중일 때만 붙고(아니면 409), 서비스가 끝나거나 에이전트를 끝내면 닫는다. 호스트 앱은 끊기면
  1·2·4·8·15초 뒤 다시 붙고, 거절당하면 멈췄다가 30초 뒤 다시 해 본다. 15초마다 ping, 45초 동안 아무것도 오지 않으면 끊긴 것으로 본다.
- 같은 id·관리 키로 다시 보내면 이미 받은 서비스를 돌려준다(응답을 놓친 호스트가 다시 확인).

**알고 쓰기**

- 마감은 에이전트 PC 시계로 잰다. 에이전트 PC가 재시작·로그오프·절전으로 멈춘 동안은 서비스도 멈춘다(다시 켜면 이어서 한다).
- 서비스 중에는 에이전트 PC에 EXCEL.EXE가 뜨지 않는다. 마감 저장 때만 저장 프로세스 하나와 숨은 Excel 하나가 떴다가 끝난다(서비스가
  여럿이면 차례로). 수식 칸은 서비스 중에 다시 계산하지 않는다(참여자 화면의 수식 결과는 넘길 때 값, 저장한 파일은 Excel이 계산한다).
- 관리자 PC에서 저장한 파일은 그 PC에만 있다(에이전트의 '저장한 곳'에는 관리자 PC의 경로가 보인다).
- 에이전트로 넘긴 업무의 참여자 주소는 에이전트 PC 주소다(`http://<에이전트IP>:8090/<주소 경로>`). HTTP·IP로 사람을 알아보는 한계(7단계 보안)는 같고,
  자동 승인이라 이름만으로 들어온다.
- 호스트 앱 여러 대가 같은 업무를 다루지 않는다(관리 키는 넘긴 앱에만 있다).

시험: agent-protocol(넘길 묶음 왕복·손상 거절, 취합 데이터 왕복(저장 계획이 같다)·손상·형식 거절, 마감·이름 검사, 주소 정리·응답
읽기), collect-agent(경로 가두기 — `..`·드라이브·링크로 밖에 나가기, 같은 이름은 `_2`, 218자, 설정 기본값; `tests/api.rs` — Excel

## 범위 밖

조건부 서식, 셀 안 부분 서식(리치 텍스트), 이미지·차트·도형·메모, 여러 통합문서를 한 업무로 묶어 취합(업무마다 통합문서 하나 — 업무는 여럿 가능), 사외(인터넷) 접속·HTTPS·로그인,
자동 업데이트, 에이전트로 넘긴 업무를 이 PC로 되돌리기·다시 불러오기, 에이전트 업무를 이 PC의 원본 통합문서에 반영하기(이 PC에서는 새
파일로만 저장), 에이전트 서비스 중 수식 다시 계산, 공유 중인 업무를
에이전트로 옮기기, 여러 호스트 앱이 같은 에이전트 업무를 다루기.
행은 표 끝(맨 아래)에만, 열은 표 맨 오른쪽에만 붙인다(표 가운데 끼워 넣기는 하지 않는다). 열은 앱에서 붙인 열만 지운다(엑셀에서 불러온
열 삭제는 하지 않는다). 지운 불러온 행은 그 행 전체(표 밖 칸 포함)를 Excel에서 지우고 다른 수식의 참조는 `#REF!`가 될 수 있으며, 스냅샷
복원·되돌리기로 행은 되살리지 않는다. 값으로 바꾼 수식 칸은 되돌리기·스냅샷 복원·'Excel 값 유지'로도 수식이 되살아나지 않는다(값으로).
앱 안 수식 글자는 행을 지운 뒤 참조가 어긋나 보일 수 있다(계산·저장은 Excel이 맞춘다).
